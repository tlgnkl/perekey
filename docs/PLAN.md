# План Perekey

Perekey — свободный автоматический переключатель раскладки для macOS.
Ориентир по функциям — Caramba Switcher. Отличия: современный интерфейс,
гибкие сочетания клавиш, предсказуемость, проверяемая приватность, без подписки.

## Для кого и зачем

**Аудитория:**
- люди, которые пишут на русском и английском: мессенджеры, почта, документы;
- разработчики — им больнее всего от ложных срабатываний в коде и терминале;
- те, кто пересел с Windows и привык к ⌥⇧ / ⌃⇧;
- пользователи Punto Switcher: у него для Mac только сборка под Intel, без
  Rosetta он не запустится.

**Почему не системное переключение macOS:** в нём нет перенабора, нет
автопереключения и нет сочетаний из одних модификаторов, кроме Caps Lock и 🌐.

**Чем Perekey лучше бесплатного клона:**
1. **Предсказуемость.** Отмена одним Backspace. Отменённое слово запоминается
   и больше не переключается. Запоминание видно: подсказка называет слово, и
   его можно сразу забыть.
2. **Честный режим для кода.** В терминалах и IDE по умолчанию только ручное
   переключение.
3. **Проверяемая приватность.** Открытый код, набранный текст только в памяти,
   сеть только для проверки обновлений.

## Принятые решения

| Вопрос | Решение | Почему |
|---|---|---|
| Имя | Perekey | «Переключить» + key |
| Лицензия | GPL-3.0-or-later | Форк не может стать закрытым платным клоном. Совместима с данными под CC BY-SA 4.0 |
| Платформа | Только macOS 14+ | `MenuBarExtra`, Observation, `SMAppService`. Windows не нужна |
| Язык | Swift 6, строгая конкурентность | Один инструмент сборки. Ядро без AppKit, его легко тестировать |
| Сборка | SwiftPM + `scripts/bundle.sh` | Нет `.xcodeproj` и конфликтов `.pbxproj`. Собирается без Xcode |
| Тесты | Swift Testing, `scripts/test.sh` | Скрипт чинит запуск под Command Line Tools |

| Подпись для разработки | `scripts/dev-cert.sh` → «Perekey Dev» | Ad-hoc подпись меняется при каждой сборке, и macOS сбрасывает выданный доступ |

| Распространение | DMG, свой Homebrew tap, Sparkle 2 | В официальный cask проект с малым числом звёзд не примут |

| Сочетания по умолчанию | Shift — сменить раскладку, Option — перенабрать слово | Как в Caramba. Онбординг предлагает другие пресеты |
| Дизайн | «Стеклянная правка»: `design/mockup.html`, `DESIGN.md` | Стеклянная полоска накрывает слово, перенабирает и снимается по Backspace |

| Обучение на отменах | Видимое: подсказка «Запомнил «…» · Забыть», раздел «Выученные», галочка «Учиться на отменах» | Тихое обучение раздражает: Caramba убрала автоматические исключения в сентябре 2026 |

## Чистая комната

- Функции Caramba Switcher изучены по поведению и строкам интерфейса. Код и
  данные не декомпилировались.
- Правила и словари Caramba (`latest.clm`, `caramba.redb`) не копируем и не
  используем для обучения.
- Название и логотип Caramba не используем.
- Источник и лицензию каждого словаря записываем в `data/SOURCES.md`.

## Приватность

- Буфер слова живёт только в памяти. На диск набранный текст не попадает.
- Логи пишутся с `privacy: .private`. Набранный текст в логи не попадает.
- Сеть — только запрос appcast Sparkle. README называет этот адрес, чтобы
  его можно было проверить в Little Snitch. Проверку обновлений можно
  выключить, тогда сети нет совсем.
- Нет телеметрии, Sentry и отправки слов.
- Нет идентификаторов устройства и установки. Caramba по карточке App Store
  собирает Device ID; запрос appcast у нас идёт без него.
- Экран «Что видит Perekey» простыми словами объясняет, какой доступ нужен и зачем.

## Сочетания клавиш

### Действия

| Действие | По умолчанию |
|---|---|
| Сменить раскладку по кругу | Shift |
| Перенабрать последнее слово или выделение | Option |
| Включить или выключить автопереключение | левый ⇧ + правый ⇧ |
| Включить конкретную раскладку | не задано |
| Отменить последнее исправление | не задано (Backspace сразу после исправления работает всегда) |
| Сменить регистр слова или выделения | не задано |
| Вставить без форматирования | не задано |

### Пресеты

Код — `Sources/PerekeyCore/HotkeyPreset.swift`. Тест проверяет, что внутри
пресета ни одна комбинация не подходит под два действия.

| Пресет | Сменить раскладку | Перенабрать слово |
|---|---|---|
| `standard` (по умолчанию, как в Caramba) | Shift | Option |
| `doubleShift` | Shift | Shift дважды |
| `windowsAltShift` | ⌥⇧ | Option |
| `windowsControlShift` | ⌃⇧ | Option |
| `commandShift` | ⌘⇧ | Option |
| `separateKeys` | правый ⌘ → English, правый ⌥ → Русский | левый ⌥ |

Во всех пресетах левый ⇧ + правый ⇧ включает и выключает автопереключение.
Caps Lock — отдельная настройка (см. ниже).

**Онбординг спрашивает:** «Как вы привыкли менять раскладку?» Варианты: Shift,
как в Caramba; ⌥⇧ или ⌃⇧, как в Windows; ⌘⇧; отдельные клавиши; Caps Lock.

### Правила распознавания

Логика — `Sources/PerekeyCore/ChordDetector.swift`, покрыта тестами.

- Сочетание из одних модификаторов срабатывает на **отпускание**.
- Любой другой ввод при зажатых модификаторах отменяет сочетание: клавиша,
  клик, scroll, жест трекпада. Поэтому ⌘⇧4 — не ⌘⇧, ⌘-scroll — не ⌘,
  Shift+A — не Shift.
- Нажатие, начатое меньше чем через 0,15 с после другого ввода, не считается.
  Так Shift в быстром наборе не меняет раскладку посреди слова. Паузу
  отсчитываем от нажатия клавиши, а не от отпускания: иначе Option сразу
  после слова теряется (spike S0). Отпускание клавиши только прерывает
  текущее сочетание.
- Нажатие дольше 0,5 с не считается.
- Двойное нажатие — два одинаковых нажатия в пределах 0,4 с.
- Одиночное действие срабатывает сразу. Двойное действие не должно зависеть от
  того, что одиночное уже сработало: перенабор берёт раскладку слова из
  `WordBuffer`, а не текущую.
- Состояние модификаторов читаем из битов флагов каждого события
  (`ModifierKey.pressed(inEventFlags:)`), а не считаем нажатия и отпускания.
  Иначе после пропущенного события клавиша «залипнет».
- Левый и правый модификаторы различаются.

### Конфликты

Рекордер предупреждает, если сочетание уже занято:

| Сочетание | Где занято |
|---|---|
| ⌘Space | Spotlight |
| ⌃Space | Системная смена источника ввода |
| Shift дважды | Search Everywhere в JetBrains IDE |
| 🌐 / fn | Системное действие сработает тоже, раскладка сменится дважды |
| fn дважды | Диктовка |
| Модификатор дважды | Raycast, Alfred — если настроены |

### Caps Lock

- Вариант 1, без риска: включить системную настройку «Caps Lock переключает
  на ABC». Онбординг показывает, где она.
- Вариант 2, мгновенно: переназначить Caps Lock в F18 через свойство
  `UserKeyMapping` (`IOHIDEventSystemClientSetProperty`, публичный IOKit).
  Его же пишет `hidutil property --set`. Сам `hidutil` не зовём: на macOS 27
  `--get` печатает таблицу по каждому устройству, разбирать её хрупко.
  - Прочитать текущий `UserKeyMapping`, добавить своё, записать. Не затирать
    чужие переназначения.
  - Убрать своё при выходе.
  - Кнопка «Вернуть Caps Lock» в настройках — на случай падения.
  - Предупредить, если запущен Karabiner-Elements.

## Устройство

```
┌─ Perekey (приложение) ─────────────────────────────────┐
│ SwiftUI: MenuBarExtra, настройки, онбординг, подсказка  │
│ Настройки, исключения: JSON в Application Support       │
└──────────────┬─────────────────────────────────────────┘
               │ исполнители эффектов и источники событий:
               │ TextSink, LayoutSwitcher, FocusObserver
┌─ PerekeyInput (системный слой) ─▼──────────────────────┐
│ EventTap — два tap, свой поток с CFRunLoop              │
│ InputSources — TIS, только главный поток                │
│ Focus — AX на отдельной очереди с таймаутом             │
│ SecureInput, Permissions                                │
└──────────────┬─────────────────────────────────────────┘
               │ InputEvent → InputMachine → [Effect]
┌─ PerekeyCore (чистая логика, без AppKit) ─▼────────────┐
│ InputMachine — машина состояний: события → эффекты  ✔   │
│ ChordDetector, HotkeyPreset                         ✔   │
│ Trigger — сочетание модификаторов или клавиша + модиф. ✔│
│ LayoutMap — таблица (keyCode, флаги) ↔ строка       ✔   │
│ WordBuffer — нажатия текущего слова                 ✔   │
│ Classifier — n-граммы + словарь, сравнение двух чтений  │
│ AppModes, Exceptions — режимы программ, слова, отмены   │
│ Settings, LayoutID — снимок настроек, ID раскладки  ✔   │
└────────────────────────────────────────────────────────┘
```

### Модель ядра

- `InputEvent`: keyDown, keyUp, flagsChanged (keyCode, флаги, повтор, время,
  источник `user` / `own` / `replayed`), клик, scroll, смена фокуса, смена
  раскладки.
- `Effect`: выбрать раскладку, перенабрать (удалить N, ввести текст, целевая
  раскладка), придержать ввод, отпустить ввод, показать предупреждение.
- `InputMachine.handle(_:) -> [Effect]` — чистая функция состояния. Системный
  слой только поставляет события и исполняет эффекты, поэтому всю логику можно
  проверить на эталонных последовательностях событий.
- **Время.** Отдельный `Clock` ядру не нужен. Время приходит в каждом событии.
  Таймаут машина просит эффектом `scheduleDeadline(at:)`, системный слой
  отвечает событием `deadline`. Пока ввода нет, таймер не тикает. Пауза «на
  1 час» живёт в приложении на настенных часах, чтобы учитывать сон.
- `Output` — что сделать с самим событием (`pass` / `drop` / `hold`) и список
  эффектов. Сначала применяется судьба события, потом эффекты: придержанное
  событие может отпустить тот же ответ.
- `Settings` — неизменяемый `Sendable` снимок настроек. На поток tap
  передаётся целиком.
- `LayoutID` — input source ID из TIS, а не язык: у одного языка бывает
  несколько раскладок (ABC, U.S., Russian–PC). Язык — запасной вариант.
- `Trigger = .modifiers(chord, taps) | .key(keyCode, modifiers)`, `taps` —
  enum. Нужен для «Включить English», вставки без форматирования, Caps Lock
  после переназначения и рекордера.

### Потоки

1. **Поток tap** (`Thread` + `CFRunLoopRun`, QoS userInteractive). Здесь живут
   `InputMachine`, буфер и очередь придержки. Объект движка передаётся в
   callback через `Unmanaged`.
2. **Главный поток.** TIS (по заголовку `TextInputSources.h` он не
   потокобезопасен), построение `LayoutMap`, NSPasteboard, UI.
   `kTISNotifySelectedKeyboardInputSourceChanged` — распределённое
   уведомление. Подписываться с `.deliverImmediately`: иначе AppKit
   придерживает его, пока приложение неактивно, а приложение в строке меню
   неактивно почти всегда. Без этого ограда всегда ждала бы полные 300 мс.
3. **Очередь AX** с `AXUIElementSetMessagingTimeout` 0,1–0,25 с. AX-вызов к
   зависшей программе по умолчанию ждёт секунды; в callback это заморозит
   клавиатуру всей системы.
4. **Обмен.** Из tap наружу — `AsyncStream` или `DispatchQueue.main.async`.
   Внутрь tap — `CFRunLoopPerformBlock` + `CFRunLoopWakeUp`. Никаких
   `main.sync`. Для короткого чтения — `OSAllocatedUnfairLock` (`Mutex` требует
   macOS 15).

**Запрещено в callback:** AX, TIS, NSPasteboard, диск, любые блокировки,
которые держит главный поток.

**Бюджет.** Callback tap — p99 не больше 1 мс вместе с классификатором. В
простое CPU около 0 %: никаких таймеров, которые тикают без ввода. Бенчмарк
`InputMachine` на записанной последовательности нажатий идёт в CI и падает
при росте больше чем на 20 %. Caramba в сентябре 2026 отдельно сокращала
работу на каждом нажатии — заложим это сразу.

### Event tap

- **Два tap.** Активный (`.defaultTap`, `.cgSessionEventTap`,
  `.headInsertEventTap`) — только клавиатура: keyDown, keyUp, flagsChanged.
  Только для чтения — мышь, scroll, жесты (типы 18–20, 29–32 сырыми числами).
  Сочетание отменяют клики, scroll (22), щипок (30), свайп (31), поворот (18).
  Типы 29, 19 и 20 — нет: они идут, пока пальцы просто лежат на трекпаде, и
  на ноутбуке Shift не срабатывал бы никогда (spike S0).
  Активный tap на мыши добавил бы задержку всему вводу.
- **Отключение системой** (`tapDisabledByTimeout` / `ByUserInput`): callback
  не знает, какой из двух tap отключён, поэтому включает снова каждый
  выключенный через `CGEvent.tapEnable`, сбросить `ChordDetector.reset()`, буфер и
  очередь придержки. При повторных отключениях — пауза и запись в лог.
- **Время.** Брать `clock_gettime_nsec_np(CLOCK_UPTIME_RAW)` в callback: на
  Apple Silicon `CGEventTimestamp` бывает в тиках `mach_absolute_time`.
- **Модификаторы** читать из флагов только на flagsChanged
  (`ModifierKey.pressed(inEventFlags:)`); стрелки несут бит fn на keyDown.
  Без битов сторон — по keyCode (`ModifierKey(keyCode:)`). Caps Lock (57) и
  keyUp — это `otherInput`.
- **Свои события** помечены `kCGEventSourceUserData` и в детектор и буфер не
  попадают.
- **Сон и сессия.** На `NSWorkspace.didWakeNotification`,
  `sessionDidBecomeActiveNotification` и разблокировку экрана
  (`com.apple.screenIsUnlocked`): проверить, что tap включён, при
  необходимости создать заново; пересобрать `LayoutMap`; сбросить детектор,
  буфер и очередь придержки. На `sessionDidResignActive` — снять придержку.
  Отключённый после сна tap молча выключает весь продукт.

### Перенабор

- **Гонка со сменой раскладки есть.** Unicode-ввод от раскладки не зависит, но
  `TISSelectInputSource` доходит до программы асинхронно. Клавиши, нажатые сразу
  после Option, программа прочитает в старой раскладке.
- **Ограда.** Последнее синтетическое событие несёт метку `magic|seq`. Пока tap
  не увидел эту метку и не пришло подтверждение смены раскладки (или не прошло
  ~300 мс), события клавиатуры пользователя копируются (`event.copy()`), а
  callback возвращает nil. Потом копии отправляются заново с меткой `replayed`
  и попадают в буфер. keyUp придерживается вместе со своим keyDown.
  Replayed-событие может запустить новый перенабор. Тогда следующие
  replayed-события придерживаются снова, иначе они обгонят его Backspace.
- **Отмена.** Если сверка перед Backspace не прошла, системный слой ничего не
  отправляет и шлёт событие `retypeCancelled(seq)`. Ядро возвращает прежнюю
  раскладку, очищает буфер и снимает ограду.
- **Клик** во время ограды придержать нельзя: tap мыши только читает. Клик
  дойдёт до программы раньше придержанных клавиш. Ограда длится миллисекунды,
  поэтому миримся.
- **Как вводить:**
  1. Сначала выбрать целевую раскладку (выбрать, а не переключить: иначе в
     пресете «Shift дважды» раскладка сменится дважды).
  2. Backspace × N, затем символы. В событии — keyCode символа в целевой
     раскладке (из обратной `LayoutMap`) **и** строка
     `CGEventKeyboardSetUnicodeString`. Java, VM и RDP читают keyCode, остальные —
     строку; так основной и запасной пути сливаются.
  3. Строка — кусками до 20 UTF-16 на событие. Флаги — только Shift и
     Caps Lock из `Retype.Key.stroke`, без ⌥⌘⌃: иначе зажатый ⌥ превратит
     Backspace в ⌥⌫, а программы, которые читают только keyCode, получат
     строчные буквы вместо заглавных. Источник `.privateState`. На каждый
     keyDown — keyUp.
  4. Отправка — `CGEventPost(.cghidEventTap)`. `CGEventPostToPid` не
     использовать: такие события обходят tap и ограду.
- **AX-замена** (`kAXSelectedTextRange` + `kAXSelectedText`) — только по выбору
  для программы: во многих программах она ломает ⌘Z и форматирование.
- **Сверка перед Backspace.** Там, где есть AX, прочитать текст перед курсором и
  сравнить с ожидаемым. При расхождении — отменить перенабор. Расхождение дают:
  автодополнение адресной строки, автозамена и текстовые замены на пробеле,
  автозакрытие скобок и кавычек (х ъ ж э б ю в английской раскладке — это
  `[ ] ; ' , .`), предиктивный ввод macOS 14.
- **Не перенабирать:** если текущий источник не `kTISTypeKeyboardLayout`, если
  идёт составление текста (IME), если в слове была мёртвая клавиша, если слово
  набрано с ⌥ (раскладка Бирмана).
- **⌘Z** после перенабора откатывает ввод кусками. Исправить нельзя, пишем в
  документации.
- **Перенабор выделения.** Сначала читать через AX. Иначе — через буфер обмена:
  сохранить все типы, пометить временное содержимое
  `org.nspasteboard.TransientType` и `ConcealedType`, потом восстановить.
  Учесть, что в VS Code ⌘C без выделения копирует строку.

### WordBuffer и LayoutMap

- **`LayoutMap`** строится на главном потоке через `UCKeyTranslate` с
  `LMGetKbdType()`. Результат — неизменяемая таблица
  `(keyCode, shift, caps, option) → String` и обратная, с флагом мёртвых
  клавиш. В tap передаётся готовой. Пересобирается при смене набора раскладок.
- **Элемент буфера** — `(keyCode, shift, caps, option, layoutID)`. Клавиши
  `,` `.` `;` `'` `[` `]` в русской раскладке — буквы б ю ж э х ъ: «,eltn» →
  «будет». Классификатор смотрит на оба прочтения.
- Буфер хранит хвост разделителей: перенабор после «ghbdtn » работает. После
  перенабора буфер остаётся с перевёрнутой раскладкой: повторный Option
  возвращает слово.
- **Сбрасывают буфер:** стрелки, Home/End/PgUp/PgDn, Tab, Return, Esc, fn+⌫,
  ⌥⌫, ⌘⌫, любые ⌘- и ⌃-сочетания, mouseDown, смена фокуса или программы,
  отключение tap. Scroll не сбрасывает. Backspace удаляет последний элемент.
  Автоповтор — обычный ввод.
- Фикстуры для тестов — JSON-дампы US, ABC Extended, Russian, Russian–PC,
  Бирмана, Ukrainian (отдельная dev-утилита).

### Пароли и Secure Input

- **Пока `IsSecureEventInputEnabled()` возвращает true, детектор сочетаний
  выключен** (`ChordDetector.reset()`, события модификаторов не подаются). При
  Secure Input keyDown в tap не приходят, а flagsChanged, судя по всему,
  приходят — тогда каждая заглавная буква пароля выглядит как чистый Shift и
  меняет раскладку посреди пароля. Проверить в spike.
- Поле пароля — по `kAXSubroleAttribute == kAXSecureTextFieldSubrole`
  (subrole, не role). Chrome и Electron строят AX-дерево только после
  `AXManualAccessibility`; там пароли и так включают Secure Input, поэтому AX —
  второй уровень. Если фокус сразу после смены программы неизвестен, не
  переключать автоматически.
- **PID владельца Secure Input — best effort.** Публичного API нет. Способ —
  `IORegistryEntryCreateCFProperty(root, "IOConsoleUsers")` →
  `kCGSSessionSecureInputPID`. Недокументированный ключ, но читается публичным
  IOKit (так делают Alfred и Keyboard Maestro).

### Права

- Активный tap, по опыту Hammerspoon и Rectangle, работает при одном
  **Универсальном доступе (Accessibility)**. Input Monitoring не запрашиваем,
  если spike это подтвердит на macOS 14, 15, 26 и 27.
- После выдачи доступа пробовать `tapCreate` раз в секунду: `AXIsProcessTrusted`
  бывает устаревшим. При отзыве доступа снимать tap.
- Запускать только через `open Perekey.app`: при запуске бинарника из
  Terminal «ответственным» для TCC становится Terminal.

### Классификатор

- Сравнивает log-вероятность двух прочтений: символьная n-граммная модель плюс
  бонус за слово из словаря. Учитывает язык предыдущего слова и режим программы.
- Решает на границе слова. Внутри слова переключает только на «невозможных»
  префиксах вроде «ghb» — отдельная таблица, проверяется на каждое нажатие.
- Отдельные случаи: однобуквенные «f» / «а», «b» / «и», аббревиатуры, «iPhone»,
  «ок», «Wi-Fi». Не трогает код, URL, пути, email, слова с цифрами.
- Не трогает строки, похожие на пароль: длиннее 6 знаков, разный регистр, плюс
  цифры или знаки. Это нужно для полей, которые не помечены как пароль
  (пароль Wi-Fi в обычном поле, пароль в чате). Caramba в таком случае ставит
  English; мы не переключаем вовсе — так безопаснее.
- Не трогает капчу и другие случайные строки: если оба прочтения
  маловероятны (оба ниже порога по n-граммам и нет в словаре), слово остаётся
  как есть. Ручной перенабор работает.
- **Формат модели:** один бинарный файл, `Data(contentsOf:options:.alwaysMapped)`
  и доступ через `UnsafeRawBufferPointer`. Символьные 4/5-граммы с откатом,
  2–8 МБ. Русскому нужны словоформы, а не леммы (1–5 млн): хэш-множество с
  32-битными отпечатками или DAWG, 5–10 МБ. Bloom-фильтр не подходит.
- **Ранг частоты** — у каждой словоформы, один байт (логарифмические корзины).
  Он нужен опечаткам, аббревиатурам и ёфикатору. Отпечаток + ранг: около 5 байт
  на форму, 5–25 МБ на русский. Формат закладываем сразу, иначе этап 4а
  потребует переделать модель.
- **Стоимость** — две оценки по ≤30 символов, микросекунды: на поток tap
  ложится спокойно.
- **Сборщик** — отдельный SwiftPM executable target `perekey-model`,
  детерминированный. CI пересобирает модель и сверяет хэш. Бинарник в git не
  кладём, если сборка быстрее ~30 с.
- **Лицензии данных.** С GPL-3.0 совместима только CC BY-SA 4.0. OpenCorpora
  (CC BY-SA 3.0) — несовместима. Кандидаты: дампы Википедии (BY-SA 4.0),
  wordfreq (данные BY-SA 4.0), SCOWL; лицензию русского Hunspell проверить.
  Запасной вариант — модель отдельным файлом со своей лицензией (агрегат в
  смысле GPL), только после консультации юриста.

**Метрика качества:**
- единица — слово;
- **отложенный корпус**, не пересекающийся с данными обучения;
- категории: проза, чат, код, URL, имена, смешанный текст, строки-пароли,
  капча и случайные строки, опечатки (с этапа 4а);
- ошибки набора моделируются: тот же текст в неверной раскладке;
- считаем ложные срабатывания и полноту, порог выбираем по ROC-кривой;
- в CI — выборка ~50 тыс. слов на каждый PR, который трогает классификатор или
  данные; полный прогон — по ночам.

### Этап 4а. Исправление опечаток

Главная платная функция Caramba Pro. У нас — бесплатно и с той же отменой.

- **Кандидаты** — одна правка от набранного слова: соседняя клавиша на схеме
  клавиатуры, перестановка соседних букв, пропуск, лишняя буква. Двойная
  буква отдельно («прривет»). Корпус пар «опечатка → слово» не нужен:
  кандидатов даёт словарь и схема клавиатуры, данные с новой лицензией не
  нужны.
- **Выбор.** Исправлять, только если набранного слова нет в словаре, кандидат
  один и его ранг частоты высокий. Учитывать соседнее слово по n-граммам.
- **Не трогать:** слова с заглавной буквы в середине предложения (имена),
  аббревиатуры, слова из исключений, режим «только вручную», короткие слова
  до 4 букв.
- **Порядок.** Сначала решить раскладку, потом искать опечатку в выбранном
  прочтении. Опечатку в неверной раскладке исправлять одним перенабором.
- **Отмена и обучение** — как у автопереключения: Backspace, «Выученные».
- **Настройка** — отдельная галочка «Исправлять опечатки». Выключена по
  умолчанию, пока не пройдёт метрику.

**Готово, когда:** на отложенном корпусе с моделью опечаток неверных
исправлений меньше 0,1 % слов, исправлено не меньше 60 % опечаток. Корпус
получает категорию «опечатки».

### Этап 5. Выпуск

1. Аккаунт Apple Developer, Developer ID, нотаризация в CI (`notarytool` и
   `stapler` есть в Command Line Tools).
2. Выключатель «Проверять обновления» и managed preferences (профиль MDM
   задаёт настройки и запрещает сеть). Закрывает сценарий «для организаций,
   без интернета».
3. Universal-сборка: `swift build --arch` требует XCBuild, поэтому две сборки
   (`--triple arm64-apple-macosx14.0` и `x86_64-…`) и `lipo -create`. DMG.
4. Sparkle 2 (binaryTarget работает и с CLT): встроить в `Contents/Frameworks`,
   rpath через `install_name_tool`, подписывать изнутри наружу (Autoupdate,
   Updater.app), переподписывать своим ключом. Для приложения в строке меню —
   мягкие напоминания. Ключ EdDSA — только в секретах CI.
5. Ресурсы копировать в `Contents/Resources` и брать из `Bundle.main`:
   `Bundle.module` исполняемого target ищет бандл в корне `.app` и ломает подпись.
6. CI: job с `xcode-select -s /Library/Developer/CommandLineTools`, чтобы путь
   «без Xcode» проверялся; версию раннера закрепить.
7. Свой Homebrew tap. Официальный cask — когда проект наберёт аудиторию.
8. Лендинг на GitHub Pages.

  1. Запустить TextEdit, Safari со страницей `data:` и textarea, Terminal с
     `cat > file`, шаблон Electron, VS Code.
  2. Отправить нажатия.
  3. Проверить результат через AX value или файл.

  статус, отдельно для macOS 14, 15, 26 и 27.

## Риски

| Риск | Что делать |
|---|---|
| Перенабор ломается в Electron, браузерах, терминалах | Unicode-ввод, режимы программ, e2e-стенд, матрица совместимости |
| Ложные срабатывания раздражают сильнее пропусков | Консервативный порог, отмена Backspace, обучение на отменах, корпус в CI |
| Пользователь печатает во время перенабора | Придерживать ввод в tap до конца перенабора |
| Автодополнение съедает первый Backspace | Тест в e2e, особый режим для таких полей |
| Менеджеры буфера обмена сохраняют временный текст | Типы `TransientType` / `ConcealedType`, сначала AX |
| `hidutil` затирает чужие переназначения Caps Lock | Читать и объединять, восстанавливать при выходе, кнопка «вернуть» |
| Доступ TCC слетает после пересборки | `dev-cert.sh` сейчас, Developer ID к релизу, bundle ID не менять |
| Event tap отключается системой | Свой поток, лёгкий callback, переподключение, сброс детектора и буфера |
| Tap не работает после сна или блокировки экрана | Проверка и пересоздание tap на пробуждении и разблокировке, пункт в spike и критерий задачи 4 |
| Задержка ввода и нагрузка на CPU растут незаметно | Бюджет p99 ≤ 1 мс, бенчмарк в CI, без таймеров в простое |
| Автопереключение портит капчу | Правило «случайная строка», категория в корпусе, ⇧+⇧ выключает автопереключение |
| Владельцы macOS 12–13 не могут поставить Perekey | Решение принято сознательно, пересмотреть по спросу |
| Зависший активный tap замораживает клавиатуру всей системы | Никаких AX и TIS в callback, AX с таймаутом на своей очереди |
| `TISSelectInputSource` доходит до программы с задержкой | Ограда: придержка ввода до подтверждения смены раскладки |
| AX в Chrome и Electron недоступен без `AXManualAccessibility` | AX — второй уровень защиты, основной — Secure Input |
| Заглавные буквы в пароле при Secure Input выглядят как Shift | Детектор выключен, пока включён Secure Input |
| Лицензии словарей | Только совместимые данные, `data/SOURCES.md` |
| Тихое обучение запоминает лишнее | Подсказка называет запомненное слово, «Забыть» одним нажатием, раздел «Выученные», галочка «Учиться на отменах» |
| Неверное исправление опечатки хуже самой опечатки | Галочка выключена по умолчанию, один кандидат, высокий ранг, отмена Backspace, категория в корпусе |
| Автопереключение отдаёт первые буквы следующего слова старой раскладке | Та же ограда, что у перенабора, e2e-тест на быстрый набор |
