# Стенд качества

Что меряет стенд, из чего он состоит и по каким правилам считает. Старый
замер классификатора (`perekey-eval run`, `scripts/eval.sh`) — в
`docs/classifier.md`; стенд его не трогает.

Стенд судит не одно слово, а набор. **Случай** — что делают пальцы человека и
какой текст он хотел. **Наборщик** превращает шаги случая в нажатия клавиш и
время. **Испытуемый** получает эти нажатия и отдаёт итоговый текст поля.
**Счётчик** сравнивает текст с задуманным и даёт каждому токену **исход**.

```
случай (.jsonl) ─► наборщик ─► события ─┬─► Null (без Perekey) ─┐
                                        └─► испытуемый ─────────┴─► счётчик ─► исходы ─► файлы прогона
```

Код: `Sources/PerekeyDesk` (стенд вокруг машины, без Foundation, как ядро) и
`Sources/PerekeyEvalKit` (случаи, наборщик, испытуемые, счёт, файлы).
`PerekeyCore`, `PerekeyInput` и `Perekey` о стенде не знают. Данные стенда —
в `eval/`, данные модели — в `data/`; сборщик модели `eval/` не читает
(тест `DataSeparationTests`).

## Как запустить

Нужны источники: `scripts/fetch-data.sh lexicon wikifreq pairs heldout` и модель
`scripts/build-model.sh`.

| Что нужно | Команда |
|---|---|
| Всё, как в CI: собрать случаи, сыграть, проверить планки | `scripts/quality.sh --self-check` |
| То же и сравнить с коммитом | `QUALITY_BASE=origin/main scripts/quality.sh --self-check` |
| Уровень `full` и отчёт HTML | `scripts/quality.sh --full --report html` (файл `.build/quality/report.html`) |
| Только собрать случаи набора | `perekey-eval cases build --only prose.tatoeba --out .build/quality/cases/ci` |
| Сыграть случаи и увидеть сводку | `perekey-eval play --cases eval/cases --model .build/model --out .build/quality/run` |
| Прочитать прогон | `perekey-eval report .build/quality/run` (`--format html --out r.html`, `--slices`, `--profile chat`) |
| Что починено и что сломано между двумя прогонами | `perekey-eval diff .build/quality/run-base .build/quality/run-head` |
| Посмотреть один случай по событиям | `perekey-eval case --cases eval/cases --id <id> --model .build/model` |
| Проверить сам стенд | `perekey-eval selfcheck --cases eval/cases --model .build/model --mutants` |
| Собрать пакет случаев | `perekey-eval cases pack --tier ci --out layoutbench-v1-e1.tar.zst` (раздел «Пакет случаев») |
| Сыграть случаи в настоящей программе и сверить с Machine | `perekey-e2e play …`, `perekey-eval fidelity …` (раздел «Настоящая программа») |

Всё в `.build/quality/` не попадает в git. Остальные команды и флаги — в разделе
«Команды».

## Случай

Файл `.jsonl`: одна строка — один случай, UTF-8, ключи отсортированы, без
пробелов. Чтение строгое: неизвестное поле, неизвестный шаг или другая
версия — ошибка. Строка, прочитанная и записанная снова, даёт те же байты.

| Поле | Обязательное | Смысл |
|---|---|---|
| `v` | да | Версия формата, `1` |
| `id` | да | `<набор>/<сценарий>/<12 hex>`: первые 12 hex FNV-1a 64 от полей `layouts`, `start`, `env`, `warmup`, `script`, `want`. Каждое поле — JSON с отсортированными ключами, между ними U+001F. Нет `env` — как `{}`, нет `warmup` — как `[]` |
| `suite`, `scenario` | да | Набор и сценарий |
| `split` | да | `dev` или `test`. Написанные руками случаи — `dev` |
| `epoch` | нет, 1 | Эпоха выборки |
| `layouts` | да | Снимки из `eval/layouts/` в системном порядке |
| `start` | да | Раскладка в начале, одна из `layouts` |
| `env` | нет | Среда, ниже |
| `warmup` | нет | Шаги до измеряемой части: их токены не считаются, порча видна как `spill` |
| `script` | да | Шаги измеряемой части |
| `want` | да | Текст, который человек хотел, целиком, вместе с `warmup` |
| `tokens` | да при `scoring: token` | Токен измеряемой части: `t` — текст; `lang` — язык или `-`; `err` — ошибка человека: `none`, `layout`, `typo`, `caps`, `doublecap`, `hyphen`, `yo`, `abbrev`; `accept` — другие верные формы; `tags`; `w` — вес, умолчание 1 |
| `scoring` | нет, `token` | `token` — исход по токенам; `case` — текст целиком и `checks` |
| `checks` | нет | `{"layout":"Russian"}` — раскладка в конце; `{"corrections":N}` — показано правок; `{"undone":N}` — отменено |
| `fold` | нет | `yo`: «ё» и «е» равны |
| `tags`, `meta` | нет | Классы случая; `meta` — любой JSON: `why` (что держит случай), `issue`, `status` у сбоев |

`env`: `app` (`com.apple.TextEdit`), `mode` (`auto`, `manualOnly`, `off`),
`settings` (пресет, `default`), `field` (`plain` или `blind`), `pace` (`calm`
или `burst`), `lag` (0), `prior` (счёт слов по языкам для `LanguagePrior`),
`exceptions`, `alwaysFix`, `secureInput` (false). В скобках — умолчание.

**Шаги.** Список закрыт.

| Шаг | Смысл |
|---|---|
| `{"type":"привет ","on":"Russian"}` | Нажать клавиши, которые печатают этот текст в раскладке `on`. Активная раскладка может быть другой: в этом ошибка. Символ, которого `on` не печатает без ⌥ и Caps Lock, — ошибка случая |
| `{"layout":"ABC"}` | Человек сам выбрал раскладку в системе |
| `{"hotkey":"switchLayout"}` | Сочетание действия из настроек случая: `switchLayout`, `convertLastWord`, `toggleAutoswitch`, `changeCase`, `undoLastCorrection`. Без привязки в пресете — ошибка случая |
| `{"key":"backspace","n":2,"mods":["option"]}` | Клавиша: `backspace`, `return`, `tab`, `escape`, `left`, `right`, `up`, `down`, `space`, `enter`; модификаторы `shift`, `option`, `command`, `control` |
| `{"click":"end"}` | Щелчок: `start`, `end`, число (каретка после стольких символов), `hint` (кнопка подсказки) |
| `{"focus":{"app":"…","secure":false,"known":true}}` | Смена фокуса; поле очищается, как новое |
| `{"mode":"manualOnly"}` | Режим программы |
| `{"capsLock":true}` | Caps Lock включён или выключен |
| `{"select":4}` | ⇧← столько раз |
| `{"secureInput":true}` | Secure Input |
| `{"wait":0.5}` | Пауза, секунды |
| `{"pace":"burst"}` | Сменить темп |
| `{"undo":"button"}` | «Отменить» в подсказке последней правки |

**Проверка** (`perekey-eval cases check`, и та же перед `play`):

1. Поля на месте, `v` равен 1, `id` равен хэшу. Неверный `id` команда
   печатает вместе с верным.
2. Каждый символ каждого `type` печатается в своей `on`. Раскладки, `start`,
   `on`, шаги `layout` — из `layouts`; пресет известен; у `hotkey` есть привязка.
3. **Текст цели** — что дали бы шаги, если бы каждый `type` печатался в своей
   `on`, с клавишами правки, щелчками и выделением; пока шаг `capsLock`
   держит Caps Lock включённым, буквы идут заглавными. Его токены после
   `warmup` равны `tokens[].t`, где `err` — `none` или `layout`, и отличаются,
   где `err` другой. Исключение — `err: hyphen`: дефис, набранный пробелом,
   делит токен, и тогда число токенов цели может быть больше; проверка
   требует, чтобы буквы цели и токенов совпали без дефисов и пробелов.
4. Токенов измеряемой части `want` столько же, сколько `tokens`; токены
   `want` — это `warmup` и `tokens[].t` через пробел.
5. Строка канонична: ключи отсортированы, пробелов нет.

Случай с ошибкой не играется, команда выходит с кодом 2.

Написанные руками случаи: `eval/cases/flow.basics.jsonl` (поведение
программы вокруг слова, `scoring: case`) и `eval/cases/incidents.jsonl`
(реальные сбои; `meta.status`: `open` — ждёт починки, `fixed` — должен
проходить).

## Наборщик и стенд

**Наборщик** (`Typist`) — чистая функция случая: те же шаги, те же события.
Числа — в `Typist.Options`.

1. **Shift** нажимается как модификатор: Shift вниз, клавиша, Shift вверх.
   Заглавные подряд идут под одним удержанием. Одинокий Shift в пресете по
   умолчанию переключает раскладку, поэтому Shift вокруг клавиши обязателен.
   Тест: 1000 слов с заглавными не меняют раскладку.
2. **Темп.** `calm` — клавиша вниз через 0,05 с после прошлой клавиши
   вверх, вверх через 0,02 с, как `Desk.press`. `burst` — 0,03 и 0,01 с.
3. **Сочетание** берётся из настроек случая. Пауза 0,3 с после последней
   клавиши, модификаторы вниз, 0,08 с, вверх (`Desk.tap`): `ChordDetector`
   не считает сочетанием нажатие, начатое меньше чем через
   `minIdleAfterTyping` после набора. Двойное нажатие — два нажатия через
   0,1 с.
4. **Конец случая** — пауза 2 с: проходят сроки ограды, стенд догоняет.

Время считается в микросекундах, поэтому суммы шагов точны.

**Стенд** (`EvalDesk`) — система вокруг `InputMachine`, по образцу
`Desk` (`Tests/PerekeyCoreTests/Desk.swift`) и драйвера `perekey-bench`.

1. **Клавиша.** Сначала решение о событии, потом эффекты. `pass` и клавиша
   вниз не от Perekey печатается в поле в раскладке программы; `hold`
   ждёт `releaseHeld`; `drop` — ничего. Клавиши с ⌘ и ⌃ не печатают.
   `flagsChanged` не придерживается, что бы ни ответила машина (`Desk.tap`).
   Caps Lock — состояние стенда: пока он включён, к клавишам добавляется
   его флаг; эффект `capsLockOff` его выключает.
2. **Поле** с кареткой и выделением слева от неё (`TextField`): печать
   заменяет выделение, Backspace, ⌥⌫ (слово), ←, →, ↑ (в начало), ↓ (в
   конец), Return (`\n`), Tab (`\t`), щелчок.
3. **Эффекты** — как `InputEngine.execute`. Пара `selectLayout` и
   следующий за ним `retype` и `convertSelection` ждут главного потока,
   пока стенд догонит. `retype` без `selectLayout` (правка в своей
   раскладке) исполняется сразу. Проверка каретки берётся в момент эффекта
   `retype`, как `InputEngine.beginCheck`: в поле `plain` перенабор слова
   (`deleteCount` > 0) с текстом слева от каретки, который не кончается на
   `expected`, отменяется. Поле `blind` (нет AX: Electron, терминал) не
   сверяет. `releaseHeld` возвращает придержанное как `replayed` через
   0,0005 с; `scheduleDeadline` запоминает срок; остальное идёт в журнал.
   «Отменить» шлёт `undoLastCorrection` с `seq` последней правки; правок
   не было — шаг пропускается.
4. **Перенабор** — как `InputEngine.postIfPending`. Машина ждёт другой
   `seq` (ограда уже снята) — перенабор не печатается, машина получает
   `inputLost`. Проверка каретки не прошла — `retypeCancelled`. Иначе
   удалить, вставить, `retypePosted`, синтетические клавиши.
   **Догнать** (`settle`), как `Desk.settle`: по очереди ответить на чтение
   выделения (выделенный текст или пустой); выбрать раскладку, напечатать
   её перенабор, затем `layoutChanged`.
5. **Отставание.** Стенд догоняет, когда наборщик прислал ещё `env.lag`
   нажатий после появления работы, или когда между событиями прошло не
   меньше 0,05 с модельного времени — что раньше. `lag` 0 — сразу после
   события. В темпе `calm` промежуток между клавишами 0,05 с, поэтому стенд
   догоняет перед каждой клавишей, как `Desk.press`.
6. **Сроки.** Перед событием со временем не меньше срока стенд шлёт
   `.deadline`. Пауза сначала догоняет, потом двигает время и шлёт
   созревшие сроки: последняя правка случая не теряется до срока ограды.
7. **Старт.** `InputMachine(settings:layouts:currentLayout:classifier:)`,
   `focusChanged(env.app)`, `appModeChanged(env.mode)`, при `env.prior` —
   `languageContextChanged`, при `env.secureInput` — `secureInputChanged`.
   В режиме `off` программа убирает сочетания (`InputController`), и стенд
   шлёт `settingsChanged` без них.

**Пресеты настроек** (`EvalSettings`):

| Пресет | Что включено |
|---|---|
| `default` | как в выпуске: автопереключение, опечатки, двойные заглавные, перенабор фразы. Тест сверяет его с `Settings()` поле за полем |
| `all` | всё из `TextCorrections`: плюс Caps Lock, аббревиатуры, «ё», дефис |
| `layout-only` | только автопереключение |
| `off` | ничего само; ручные сочетания работают |

`env.exceptions` и `env.alwaysFix` дописываются в пресет.

**Испытуемые.**

- `machine` — `InputMachine` в `EvalDesk` с моделью прогона. Модель и
  классификатор создаются один раз на набор языков. `--options <json>` —
  поля `Classifier.Options` поверх умолчаний; таблица имён — в
  `ClassifierOptions`, тест падает, если в `Options` появится поле, которого
  в ней нет. Пороги `TypoCorrector` снаружи не задать: `WordJudge` создаёт
  корректор с умолчаниями.
- `null` — поле без переключателя: клавиши в активной раскладке, выбор
  раскладки человеком, клавиши правки, щелчки, своё сочетание
  `switchLayout` (человек без Perekey переключает системным). На другие
  сочетания не отвечает. Null — постоянная база исходов, поэтому его
  сочетание подчиняется тем же правилам, что у машины: в режиме `off` его
  нет (программа убирает сочетания), под Secure Input тоже; Caps Lock и
  клавиши рвут сочетание в том же порядке, что `InputMachine`.
- `oracle` — возвращает `want`. Для проверки случаев и счётчика.

**След.** Что машина знает о своих действиях и решениях: переключение,
правка (вид, причина, счёт, «внутри слова»), отмена, отменённый перенабор;
и, для слов без действия, решение: `kept` — классификатор судил слово и
оставил (причина, счёт, запас), `notJudged` — слово не судили (причина
`skip:<почему>`: `appMode`, `secureField`, `secureInput`, `unknownFocus`,
`noClassifier`, `autoswitchOff`, `notPlain`, `leftAlone`, `noOtherLayout`).
Запись привязана к событию наборщика, на котором судили слово (для
перенабора — к событию, которое его попросило). Счётчик по следу исходов не
меняет: след даёт только метки и признаки (проверяет тест: след включён и
выключен дают одинаковые `cases.tsv`, `summary.json`, `counts.tsv`,
`words.tsv`).

След оставленных слов берётся из `JudgeTrace` (`InputMachine(tracesJudgements:)`).
Машина судит слово второй раз ради объяснения, поэтому след включает только
`MachineSystem` (`CaseSetup.tracesJudgements`, по умолчанию да; `Runner.Config`).
Выключенный след — ни одной лишней операции: `EvalDesk.Setup` по умолчанию
его не включает, стенд бенчмарка и тесты ядра его не видят.

## Исходы

**Токен** — наибольший отрезок без пробельных символов. Пробелы и переводы
строки в конце текста не считаются.

**Выравнивание** (`Aligner`). Правка может слить или разрезать токены
(«во первых» → «во-первых»). Равные списки токенов идут токен к токену.
Иначе — самое дешёвое выравнивание:

| Операция | Цена |
|---|---|
| 1:1, равны | 0 |
| 1:1, не равны | 1 + расстояние Левенштейна / длину большего |
| 2:1 или 1:2, склейка двух без пробела или через дефис равна одному | 0,5 |
| 2:1 или 1:2 иначе | 3,5 |
| токен пропал или лишний | 2 |

При равной цене: 1:1, слияние, разрез, пропажа, лишний. Правило склейки
только сопоставляет токены. Группа токенов `want` (один токен или два при
слиянии) верна, если текст вывода, сопоставленный ей, равен тексту группы
по свёрткам или входит в `accept` первого токена группы. «во первых» при
`want` «во-первых» неверно, «по новому» при «по-новому» — тоже, у Null и у
испытуемого одинаково. Слияние без `accept` всегда неверно (определение 7.2). Пропавший токен неверен. Лишний токен вывода
делает неверной группу слева от себя целиком, оба токена слияния (первый
токен, если слева ничего нет). Вывод Null выравнивается с тем же `want`
тем же правилом.

**Исход токена** измеряемой части:

| У Null | У испытуемого | Исход |
|---|---|---|
| верно | верно | `ok` |
| верно | неверно | `harm` — вред |
| неверно | верно | `fixed` — починено |
| неверно | неверно, вывод тот же | `miss` — пропуск |
| неверно | неверно, вывод другой | `botched` — порча |

`disputed` — спорно — вместо `harm` в корпусных наборах: см. «Спорно и тихо».

Токен `warmup`, вышедший неверно, — `spill`. Определение не знает, как
устроен испытуемый: счёт получает только случай и два текста.

Метки к `harm` и `botched`: `form` — `layout`, если вывод равен клавишам
токена в другой раскладке случая, иначе `edit`; `cascade` — испытуемый сам
сменил раскладку перед токеном (после последнего выбора человека), а сам
токен не трогал (по следу); `silent` — тихая (см. «Спорно и тихо»).

**Случай.** `exact` — все токены верны, `warmup` тоже; для `scoring: case` —
текст (без пробелов в конце, со свёртками) равен `want`.

**Проверки случая** (`checks`: раскладка в конце, показано и отменено
правок) читают то, что испытуемый сообщает о себе, а счёт — только текст
(правило 2.7). Поэтому их считает не счётчик, а `Runner.failedChecks` над
`RunResult`: это метка случая. На `exact`, исходы и код возврата она не влияет:
`failedChecks` — только метка; гейт по ним — планка `zero` с метрикой `checksFailed` («Планки и CI»). В
файлах прогона — столбец `checks` и счётчик `checksFailed`. `lag` в сценариях `slip.*` и `stuck` — сколько токенов от первого
токена с `err: layout` до первого верного; верного нет — длина измеряемой
части. **Событие вреда** — подряд идущие токены `harm` одного случая.

**Признаки токена** для срезов: `lang`, `len` (`1-2`, `3`, `4`, `5-7`,
`8+` букв), `pos` (`first`, `mid`, `last`), `ctx` (`cold`, `agree`,
`against`, `mixed` по трём предыдущим словам), `cap` (`lower`, `Title`,
`UPPER`, `inner`, `mixed`), `punct` (`none`, `lead`, `trail`, `both`,
`inside`), `digits`, `err`, `end` (`space`, `punct`, `return`, `tab`,
`none`), `tags` (теги случая, затем теги токена); из следа — `reason`,
`margin` (на сколько бит решение держится: `<3`, `3-10`, `10+`; у
переключения и правки — счёт минус порог, у оставленного слова — порог минус
счёт; решение не с той стороны порога (бывает и у переключений, и у
оставленных слов) попадает в `<3`; пусто, если второе чтение не слово),
`early`, `kind`.
Из следа признаки есть у каждого слова, которое судили или не судили, а не
только у переключённых.
Признаки, которым нужен лексикон, модель или списки, прогон считает только
с `--cache` или `--lexicon` (и с `--model`, для `known`):

| Признак | Значения |
|---|---|
| `known` | `yes`, если форма слова есть в модели языка токена (`LanguageModel.Language.rank(of:)`); `no`; `-` без букв |
| `zipf` | диапазон частоты слова по лексикону: `<2`, `2-3`, `3-4`, `4-5`, `5+`, `none` (слова нет в лексиконе) |
| `collision` | `yes`, если клавиши токена в другой раскладке случая дают слово лексикона с Zipf от 3 («vs» и «мы»); `no`; `-` |
| `seen` | `yes`, если слово есть в списках `data/<язык>/*.txt` или `data/mixed/*.txt`; `no` |

«Слово» токена — токен без знаков по краям, в нижнем регистре; «ё» и «е»
равны, как и заглавные со строчными.

## Спорно и тихо

Оба правила считает стенд по лексикону (раздел «Лексикон»), а не испытуемый.
Без лексикона их нет, и прогон об этом говорит.

**Спорно (`disputed`).** В настоящем тексте есть свои опечатки. Правка такой
опечатки по наивному счёту — вред. Правило одно для `dev` и `test`, без
подглядывания: `harm` с `form == edit` становится `disputed`, если вместе:

1. слова `want` нет в лексиконе (язык токена);
2. вывод есть в лексиконе с Zipf не меньше 3;
3. они различаются одной правкой: вставка, пропуск, замена или перестановка
   соседних букв (расстояние Дамерау–Левенштейна 1), либо только дефисом или
   «ё».

Правило действует только в корпусных наборах. В наборах классов и правок
слова (`class.*`, `protect.*`, `typos.*`, `flow.*`, `yo`, `hyphen`,
`doublecap`, `capslock`, `abbrev`, `incidents`) задуманное известно точно, и
`disputed` там нет: «мердж → мардж» в `class.oov` — вред. `disputed` не входит
ни во вред, ни в остаток О, ни в Т; отчёт печатает его отдельным столбцом. Но
`exact` случая остаётся по тексту: токен вышел не таким, как `want`.

Для части `dev` решение человека лежит в `eval/noise/<набор>.tsv`, по строке
на токен, поля через табуляцию:

```
<id случая>  <номер токена>  source-typo|harm  [принятая форма]
```

Номер — тот же, что `index` в `events.jsonl`: среди токенов `want`, `warmup`
первым. `source-typo` с формой добавляет её в `accept` токена; токен тогда `ok`.
`harm` возвращает вред. Строки с `#` — комментарии. Для части `test`
файла решений нет: решения из файла для её случаев игнорируются, действует
правило. `run.json` хранит SHA-256 файлов решений.

**Тихая (`silent`).** Метка `harm` и `botched`: вывод — слово лексикона на
письме одного из языков случая (кириллица — `ru`, `uk`, `be`, `kk`; латиница —
`en`). Такой результат человек не замечает. Т — это тихие вред и порча на 1000
слов.

## Лексикон

Нужен, чтобы ответить на «настоящее ли это слово». Это не то же, что `known`
(«видела ли слово модель»). Файлы — `lexicon-<язык>.tsv` (слово, Zipf с двумя
знаками, слова в порядке байтов) в каталоге `--lexicon` (умолчание
`.build/quality`). Если файла нет, `play --cache <кэш данных>` собирает его из
тех же файлов кэша, что читает модель, своим кодом поверх читателей
`PerekeyModelKit`:

| Язык | Частоты | Словоформы |
|---|---|---|
| `ru` | wordfreq `large_ru` | Hunspell `ru_RU` |
| `en` | wordfreq `large_en` | SCOWL `en_US-large` |
| `uk` | wordfreq `large_uk` | нет |
| `be` | `wikifreq/large_be` | Hunspell `be-official` |
| `kk` | `wikifreq/large_kk` | нет |

В лексикон входят все словоформы словаря (Zipf слова из wordfreq, если оно
там есть, иначе 0) и слова wordfreq с Zipf от 2. Файл — чистая функция
кэша; `run.json` хранит его SHA-256. Списки `data/` читает `play --data`
(умолчание `data`): так отмечается `seen`.

## Метрики

Счёт — по токенам измеряемой части; «слова» — токены хотя бы с одной
буквой. На 1000 слов, ‰:

| Метрика | Формула |
|---|---|
| В — вред | `harm` / слова; рядом события вреда / слова |
| Т — тихий вред | `harm` и `botched` с меткой `silent` / слова |
| Спорно | `disputed` / слова |
| П — пропуск раскладки | `miss` с `err: layout` / токены с `err: layout` |
| Пч — порча | `botched` / токены с `err` не `none` |
| О — остаток | неверные у испытуемого / слова |
| О₀ — без Perekey | неверные у Null / слова |
| Чисто | доля случаев `exact` |

Интервалы, профили, срезы и сравнение двух прогонов — в разделах
«Статистика», «Профили», «Срезы», «Отчёт» и «Сравнение».

**Числа планок.** Планки (`eval/gates.json`) читают не доли, а число событий
в группе случаев. Имена:

| Имя | Что считает |
|---|---|
| `fail` | случаи, где текст не равен задуманному (`scoring: case`) или есть неверный токен |
| `exact` | случаи `exact`; `direction: up`: число не должно падать |
| `fixed` | токены `fixed`: ошибка человека исправлена |
| `harm` | токены `harm`: верное слово испорчено |
| `harm.incidents` | события вреда: подряд идущие токены `harm` одного случая считаются раз. К набору `incidents` отношения не имеет |
| `silent` | `harm` и `botched` с меткой `silent` |
| `botched` | токены `botched`: неверное слово стало другим неверным |
| `disputed` | токены `disputed` |
| `miss` | токены `miss`: ошибка человека осталась |
| `miss.layout` | `miss` у токенов `err: layout` |
| `spill` | токены `warmup`, вышедшие неверно |
| `checksFailed` | случаи, где не прошла проверка `checks` |

Эти же слова — метрики таблиц и отчёта: Пч — `botched` на токены с ошибкой,
О — неверные токены на слова, «Чисто» — доля `exact`.

## Статистика

Числа считает `Stats`; каждое число в `PerekeyEvalKit` — в `Stats.Options` с
пометкой, откуда оно.

- **Доля в срезе** — интервал Уилсона 95 % (z = 1,96). Проверка: 5 из 10 дают
  0,237–0,763; 37 из 119 804 дают 0,22–0,43 ‰.
- **Основные метрики набора, сценария и профиля** — бутстрап по случаям
  (случай — кластер): 1000 выборок, зерно 1 (`SplitMix64`), перцентили 2,5 и
  97,5, линейная интерполяция между рангами. Профиль считается по слоям: в
  каждой выборке случаи берутся внутри каждого набора, как есть в наборе.
- **Ноль событий** из n слов печатается как «0 (≤ 3/n)»: верхняя граница
  по правилу трёх.
- **Сравнение двух прогонов** — на общих случаях; случаи, где число токенов
  вреда (пропуска, порчи…) изменилось, делятся на «лучше» и «хуже». Точный
  двусторонний биномиальный критерий Мак-Немара даёт p: 9 лучше и 3 хуже —
  0,146.

Рядом с каждой метрикой отчёт печатает число событий и слов.

## Профили

`eval/profiles.json` — веса корпусных наборов: `{"profiles":{"chat":{"chat.tatoeba":0.75,…}},"version":1}`.
Метрика профиля — взвешенное среднее метрик наборов. Откуда берутся числа
шапки отчёта:

| Число | Сценарии |
|---|---|
| В — вред | `clean.*` |
| О и О₀ — остаток и остаток без Perekey | `stuck`; набор без `stuck` — `slip.*` |
| Т, чисто | все сценарии |

Набора профиля нет в прогоне — отчёт перечисляет недостающие и пересчитывает
веса остальных. Наборы классов в профили не входят.

Необязательные поля файла: `caveats` — профиль → строка, которую отчёт печатает
крупно («ВНИМАНИЕ, профиль …») под таблицей профилей; `notes` — профиль →
пояснение для читателя файла, отчёт его не читает. Профиль `chat` пока стоит на
`chat.tatoeba` 0,75 и `lang.russian-se` 0,25 (план: 0,3 и 0,1 из 0,3 + 0,1 + 0,6, без
`social.ru`): набор разговорного русского не построен, лицензия Taiga не подтверждена.
Тест следит, что профили называют только наборы с манифестом и что веса дают 1.

## Срезы

`slices.json` хранит счётчики по каждому значению каждого признака и по каждой
паре значений двух признаков по всем токенам измеряемой части, включая `ok`
(пары — от 50 слов). Поля счётчика: `tokens`, `words`, `fixed`, `harm`,
`miss`, `botched`, `disputed`, `silent`, `layoutErrors`, `missLayout`,
`wrongNull`. Тег значит `tags=<тег>`. Пара называется `признак=значение &
признак=значение` в порядке `lang`, `len`, `pos`, `ctx`, `cap`, `punct`, `digits`, `known`, `zipf`, `collision`, `seen`, `err`, `end`, `reason`, `margin`, `early`, `kind`, `tags`.

**Худшие срезы.** Берутся все значения одного признака и все пары значений
двух признаков со словами не меньше 200. Для каждого: доля ошибок в срезе
(`harm`, `miss` и `botched` на слова) минус доля в прогоне, умноженная на
слова среза. Печатаются первые 20 с положительным числом. Это ответ на «где
ошибаемся», а не на «почему».

**Слова.** `words.tsv`: для каждого слова (токен без знаков по краям, нижний
регистр) части и набора — вхождения, вред, пропуск, порча и вес ошибок: сумма
`w` токенов, исход которых `harm`, `miss` или `botched`. Отчёт печатает первые
200 по весу, затем по числу ошибок. Слова части `test` лежат в файле, только
если прогон сыгран с `--reveal-test`.

**Причина и запас.** Из следа: сколько пропусков и вредов у каждого значения
`reason` и `margin` (остальные признаки следа — `--slices`). Пропуск
оставленного слова несёт причину, по которой классификатор его оставил
(`noise`, `shortWord`, `bothPlausible`…), или `skip:<почему>`, если слово не
судили. Вред несёт причину переключения и запас над порогом.

## Отчёт

`perekey-eval report <каталог прогона>` читает файлы прогона, а не случаи:
ему не нужны ни модель, ни раскладки. Блоки (текст, Markdown и HTML несут одни
и те же):

1. Шапка: испытуемый, коммит, хэши моделей, уровень, эпохи, настройки, версия
   счётчика, пометка «тест раскрыт».
2. Профили: вред, остаток против остатка без Perekey, тихий вред, чисто.
3. Набор × сценарий: слова, В с интервалом и числом событий, П, Пч, Т, спорно,
   О, О₀, чисто, запаздывание. Для наборов классов — отдельно В и П с весом
   токена (`w`).
4. Худшие срезы.
5. Слова (`dev`).
6. Слова, которые есть в списках `data/` (`seen`), и остальные.
7. Причина и запас до порога.
8. С `--slices` — таблица каждого признака с интервалами.
9. Сбои (`incidents`): исправлено столько-то из стольких, ждут починки.
10. Защитные наборы: вред в `protect.*`.
11. Примечания: неполный профиль, прогон без лексикона, тест раскрыт.

Форматы: `text` (умолчание), `md`, `html` и `json`. HTML — один файл без
внешних ссылок, со сортировкой по столбцам и раскрывающимися таблицами
признаков. JSON несёт те же числа с интервалами.

```
perekey-eval report <каталог прогона> [--format text|md|html|json] [--out <файл>]
                    [--profile chat,dev,office] [--profiles <файл>] [--slices] [--words N] [--reveal-test]
```

**Правило 2.8.** Без `--reveal-test` в выводе нет ни одного слова части `test`:
ни в таблицах, ни в JSON. Слова части `test` показывает только флаг, и только
если прогон сыгран с `--reveal-test`; отчёт тогда помечен «ТЕСТ РАСКРЫТ».
Флаг на прогоне без раскрытия слов не раскрывает, отчёт говорит об этом в
примечании.

## Как прочитать отчёт

`perekey-eval report <прогон>` печатает блоки раздела «Отчёт». Читать их
так:

1. **Профили** — главное число. **В** (вред) — сколько раз Perekey испортил
   верно набранное слово. **О** против **О₀** — сколько слов неверно с
   Perekey и без него, когда человек не думает о раскладке: О меньше О₀ —
   польза. **Т** — вред, который человек не заметит. Рядом с каждым числом
   стоят события и слова: «0,31 ‰ (37 из 119 804), 95 % 0,22–0,43». Ноль
   событий печатается как «0 (≤ 3/n)».
2. **Набор × сценарий** — то же по частям. `clean.*` отвечает на вопрос «не
   портит ли Perekey верный текст» (В), `slip.*` и `stuck` — «исправляет ли
   неверную раскладку» (П, О).
3. **Худшие срезы и слова** — где ошибаемся: значение признака или пара
   значений с лишними ошибками, слова с весом ошибок. Это «где», а не «почему».
4. **Сбои** (`incidents`) — сколько починенных держат, сколько ждут правки.
5. **Защитные наборы** — вред в `protect.*`.
6. **Примечания** — на что смотреть с осторожностью: неполный профиль, прогон
   без лексикона (нет `disputed` и `silent`), тест раскрыт.

Отчёт показывает слова только части `dev` (правило 2.8). Сравнение двух
прогонов — `diff`: таблица сумм с числом случаев «лучше» и «хуже» (p по
Мак-Немару) и списки «Сломано» и «Починено» по токенам.

## Сравнение

`perekey-eval diff <прогон A> <прогон B>` сравнивает два прогона на общих
случаях (по `id`; случаи только в одном прогоне считаются и не сравниваются).
Прогоны с разной версией счётчика сравнивать нельзя: команда выходит с кодом
2. Таблица: вред, пропуск, порча, тихий вред, спорно — суммы в A и B, число
случаев «лучше» и «хуже», p. Затем списки по токенам: «Сломано» (был верный
исход `ok` или `fixed`, стал `harm`, `miss`, `botched`; у случая, оцениваемого
целиком, был `exact`, стал `fail`) и «Починено» (наоборот). Переход через
`disputed` в списки не идёт. Слова части `test` — только число случаев и
наборы, если нет `--reveal-test`.

```
perekey-eval diff <A> <B> [--format text|md|json] [--list N] [--reveal-test]
```

только с `--reveal-test`. Коды выхода: 0 — успех; 1 — самопроверка не
прошла или планка не взята; 2 — ошибка входа.

**Часть `test`** (правило 2.8). Без `--reveal-test` ни файлы прогона, ни
сообщения команд не содержат слов случаев части `test`: на их месте
`(test)`. `play --reveal-test` пишет слова и ставит в `run.json`
`testRevealed: true`. `cases check` описывает ошибки случая `test` без его
слов.

`selfcheck` проверяет инварианты: Null не вредит и не чинит; Oracle точен
(по тексту: раскладки и счёта правок у него нет); машина с пресетом `off`
печатает то же, что Null, на случаях без сочетаний и «Отменить»; два прогона
машины дают те же байты `cases.tsv`, `summary.json`, `counts.tsv`, `slices.json` и `words.tsv`; каждый случай
проходит проверку. С `--suites` самопроверка собирает каждый набор дважды и сравнивает
SHA-256 файла и отчёт сборки; без `--suites` этот пункт пропускается. С `--built <каталог>`
первой сборкой считаются файлы, которые уже записал `cases build` (`build.json`), и
собирается только вторая; `--rebuild <набор,...>` ограничивает вторую сборку этими
наборами; `--skip-missing` пропускает набор, чьего источника нет в кэше. Пункт 7 —
мутанты, с `--mutants` (раздел «Самопроверка и мутанты»). `--split` выбирает часть для
пунктов 1–4; мутанты всегда играют обе части.

Пример: `perekey-eval selfcheck --cases eval/cases --model .build/model`.

## Планки и CI

`scripts/quality.sh` — обёртка по образцу `scripts/eval.sh` и `scripts/bench.sh`.

```
scripts/quality.sh [--full] [--self-check] [--report html] [--model <каталог>]
env QUALITY_BASE=<git ref>
```

1. Собирает `perekey-eval` (release) и модель (`scripts/build-model.sh`, если не
   дан `--model`).
2. `cases build --tier ci` в `.build/quality/cases/ci` (`--full` — `full`). Набор,
   чьего источника нет в кэше, пропускается строкой «пропущен: нет источника X».
   В CI (`GITHUB_ACTIONS=true`) наборы `CI_SUITES` из скрипта обязательны: нет
   одного из них — выход 2.
3. `selfcheck` на частях `dev` и на `eval/cases`; с `--self-check` и в CI — ещё
   мутанты (раздел «Самопроверка и мутанты»). Сборка дважды — для наборов
   `REBUILD_SUITES` (быстрые источники), на `--full` — для всех.
4. `play --system machine` → прогон `head` (Null играется в каждом случае сам).
5. С `QUALITY_BASE`: ссылка, которая не коммит, — выход 2 в pull request
   (`GITHUB_EVENT_NAME=pull_request`: база есть всегда, без неё `noWorse` молча
   прошёл бы) и строка в сводке на push (у первого push `before` из нулей).
   Решение принимается до любой сборки; `--check-base` останавливается на нём.
   Worktree базы во временном каталоге; поверх него копии
   `Sources/PerekeyEvalKit`, `Sources/PerekeyDesk`, `Sources/perekey-eval` и
   `eval/` из головы, чтобы база играла стендом головы и разница шла только от
   ядра. Три исхода: в базе нет стенда — «сравнивать не с чем», выход по `zero`;
   база со стендом головы не собралась — собирается со своим стендом, сводка
   помечена; не собралась и так — выход 1. Модель базы — модель головы, если
   `data/`, сборщик модели и его скрипты не изменились; иначе база строит свою.
   Собранная база (бинарник и, если нужна, её модель) лежит в
   `QUALITY_BASE_CACHE`; в CI это `actions/cache` с ключом `quality-base-<SHA базы>-<хэш
   стенда и входов модели>`. В pull request базой служит первый родитель слитого дерева (`HEAD^1`), а не `base.sha`: если `main` ушёл вперёд за время очереди, `base.sha` не имеет кода, который использует стенд слияния, база собирается дважды и шаг вдвое дольше. Скрипт сверяет отпечаток тех же входов и пересобирает
   каталог, который не сошёлся. База играет те же файлы случаев, как только собрана,
   рядом с головой и самопроверкой → прогон `base`; затем `diff base head`.
6. `perekey-eval gate` проверяет планки; сводка идёт в `$GITHUB_STEP_SUMMARY`.

**PR стенда** — тот, у которого все изменённые файлы лежат в `eval/`,
`Sources/PerekeyEvalKit/`, `Sources/PerekeyDesk/`, `Sources/perekey-eval/`,
`Tests/PerekeyEvalKitTests/`, `docs/` или это `scripts/quality.sh` (белый список,
`StandChange`; `gate --changed <файл со списком>`). Любой другой файл, в том числе
`.github/`, `Package.swift` и скрипты данных, делает PR ядра. Для него `noWorse` печатается и не гейтит: разница
может идти от стенда. `zero` и самопроверка гейтят. PR, который трогает и стенд,
и ядро, гейтится полностью.

Коды выхода: 0 — планки взяты; 1 — планка не взята или самопроверка не прошла;
2 — нет обязательного источника или случаи не собрались. Сбой загрузки
источника виден как «нет источника», а не как ухудшение качества.

### `eval/gates.json`

```
{"version":1,
 "zero":    [{"suite":"flow.*","metric":"fail"},
             {"suite":"incidents","status":"fixed","metric":"fail"}],
 "noWorse": [{"profile":"*","metric":"harm"}, {"suite":"typos.*","metric":"fixed","direction":"up"}, …],
 "accepted":[{"metric":"harm","scope":"class.*","reason":"…","pr":123}],
 "targets": [{"metric":"harm","scope":"profile:chat","value":0.5,"note":"…"}]}
```

- `zero` — число событий равно 0 в прогоне головы. `suite` — имя или образец с
  `*`; каждый набор по образцу проверяется отдельно. `status` оставляет случаи с
  таким `meta.status` (сбои); их берёт `gate --cases eval/cases`. В `zero` идёт
  только то, что уже 0 на `main`: на момент записи это `flow.*` и починенные сбои.
  Набор, которого нет в прогоне, — провал планки, а не пропуск: планка, которая
  ничего не читает, не взята. Исключение — правило с `"optional": true` (набор с
  источником в гигабайт, например `class.oov`, `class.brands`): его нет — планка
  пропущена. Сейчас ни одно правило `zero` не помечено.
- `noWorse` — число событий в прогоне головы не больше, чем в прогоне базы, на
  общих случаях (по `id`). Для профиля (`profile`) — сумма событий наборов с
  весами профиля, приведёнными к сумме 1 по наборам, которые есть в обоих
  прогонах; профиль в CI неполный (нет `tech.ruso`). Обмен «починил 12 вредов,
  сломал 3» проходит: сумма меньше. Рост вреда ради полноты не проходит.
  `direction: "up"` — число не должно падать (`fixed`, `exact`). Набор, которого
  нет в обоих прогонах, планку пропускает (строка «пропущена»): планка для
  набора появляется вместе с набором. Кроме того, если у головы нет случаев,
  которые есть у базы, и PR не стенда, провал — планка `coverage` со списком `id`
  (до 20): иначе потерянные случаи уменьшали бы сравнение молча. В PR стенда
  случаи можно переименовать и убрать; это строка примечания.
- `accepted` — осознанное исключение: рост числа, который PR принимает. Его
  добавляет тот же PR, что вызвал рост; в ревью видно причину. Срока нет: срок
  по дате ронял бы чужие PR. Каждый прогон печатает список. Перед выпуском
  список `accepted` пуст или подтверждён заново.
- `targets` — цели с числом: печатаются, не гейтят.

`perekey-eval gate <голова> [<база>] [--gates …] [--profiles …] [--cases …]
[--format text|md|json] [--list N] [--stand-pr] [--changed <файл>]`. Проваленная планка печатает
случаи, которые её сломали: `id` и числа «было → стало». Слова случая —
`perekey-eval case --id <id>`, сравнение по токенам — `diff`.

### Время шага

Бюджет шага — не больше 5 минут к задаче `build` (РЕ9). Уровень `ci` набран
под него: `tiers.ci` каждого манифеста и список `CI_SUITES` в `scripts/quality.sh`.
В список входят наборы корпусов, правок, `class.frequent`, `class.short`,
`class.collision`, `class.names`, `class.cli`, `class.code` и `protect.*` на русском.
`class.caps`, `class.translit`, `class.punct` (около трёх минут на сборку) и
украинские пары идут только на `--full`. `class.oov` и `class.brands` читают
ru.stackoverflow.com (группа `heavy`): в CI они пропускаются строкой «пропущен:
нет источника», ошибки нет (`OPTIONAL_SUITES`).

Скрипт печатает в конце секунды каждой части (`head: build …`, `base: build …`,
`cases: all`, `selfcheck`, `head: play`, `base: play`, `bars …`) и самые долгие
сборки наборов. Замер на раннере CI (3 ядра), шаг целиком:

## Самопроверка и мутанты

`selfcheck` проверяет, что сам стенд не врёт. Инварианты (1–6) описаны выше, в
разделе «Команды». Пункт 7 — **мутанты**: машина с испорченными опциями
(`--options`) или пресетом играет те же случаи, и счёт обязан сдвинуться. Не
сдвинулся — стенд слеп к такой порче, самопроверка падает.

Мутанты играют обе части, `dev` и `test`: сдвиг читается по числам, слов в
выводе нет, а событий в пять раз больше. Порог сдвига — половина измеренного
(запас вдвое, раздел 20 плана, пункт 8).

| Мутант | Метрика | Обычная машина → мутант | Сдвиг | Порог |
|---|---|---|---|---|
| `threshold: 0` | `harm` в `clean.*` | 58 → 79 | × 1,36 | не меньше × 1,18 |
| `threshold: 40` | `miss.layout` в `slip.*` | 532 → 821 | × 1,54 | не меньше × 1,27 |
| `contextBonus: 0` | `miss.layout` в `slip.warm` | 475 → 470 | × 0,989 | не больше × 0,995 |
| `contextBonus: 0` | `harm` в `clean.warm` | 13 → 13 | — | не больше обычной |

Замер: `perekey-eval selfcheck --cases eval/cases .build/quality/cases/ci --split dev
--model .build/model --mutants` на коммите ветки `eval/gates-ci`, уровень `ci`,
наборы `SELF_SUITES` и руками написанные случаи. Числа зависят от случаев: после смены уровня, наборов
или счётчика замерить заново и записать здесь и в `Mutants.all`.

**Что замер сказал иначе, чем план (12.3).**

- `threshold: 0` растит вред в `clean.*` не вдвое, а на 26 %. Классификатор не
  переключает слово, пока другое прочтение не лучше как слово: порог 0 снимает
  только запас. Даже с `readingMargin: 0`, `unknownWordExtra: 0`, `noiseCost: 0` и
  `unknownNoiseCost: 0` вред вырос бы на 55 % (60 → 93 на части `dev` при 20 000
  токенов на сценарий; замер вне CI).
- `contextBonus: 0` не растит П в срезе `ctx=agree` (45 → 45 на том же замере).
  Бонус контекста тянет к языку предыдущих слов, а в `slip.warm` предыдущие слова
  чужого языка: без бонуса П в `slip.warm` падает, а не растёт. Мутант проверяет
  это направление.

**Мутанты плана, которых пока нет в таблице.** Они ждут наборов других лейнов; когда
набор появится, строка добавляется в `Mutants.all` с порогом по факту:

| Мутант плана | Метрика | Ждёт |
|---|---|---|
| `noiseCost` и `unknownNoiseCost` × 3 | В в `protect.captcha` растёт | набор `protect.captcha` |
| Пресет `layout-only` | Починено в `typos.*` падает до 0, Т в `typos.none` падает до 0 | наборы `typos.*` |
| Пресет `all` вместо `default` | Починено в `hyphen` и `yo` растёт с 0 | наборы `hyphen`, `yo` |
| Раннее переключение выключено | П в срезе `known=нет & len=8+` растёт | флаг в `Classifier.Options`: его нет |

Пороги `TypoCorrector` так испортить нельзя: `WordJudge.setClassifier` создаёт
корректор с умолчаниями (раздел «Чего стенд не моделирует»).

## Как добавить сбой

Одна строка в `eval/cases/incidents.jsonl`, статус `open` до починки и `fixed`
после. Шаги и перенос полей из issue «False switch» — в
[eval/README.md](../eval/README.md). После статуса `fixed` случай входит в планку
`zero`: вернувшийся сбой делает шаг CI красным.

## Как добавить набор

Манифест `eval/suites/<имя>.suite.json` (раздел «Корпусные наборы»), источник
закреплён хэшем в `scripts/fetch-data.sh` и записан в `data/SOURCES.md` с
лицензией. Затем `tiers.ci` так, чтобы набор влез в бюджет шага, проверка
`perekey-eval cases check`, строка в `eval/gates.json` и, если набор описывает
человека, строка в `eval/profiles.json`. Подробно — в
[eval/README.md](../eval/README.md). Набор из источника, которого CI не качает,
в `ci` не идёт (`CI_SUITES` в `scripts/quality.sh`).

## Корпусные наборы

Набор — случаи одного происхождения. Манифест `eval/suites/<набор>.suite.json`
говорит, откуда текст, на каких раскладках его печатает человек и сколько
токенов брать. Манифест читают строго: неизвестное поле, сценарий или
значение — ошибка; имя файла равно полю `suite`.

| Поле | Смысл |
|---|---|
| `suite`, `version` (1), `about`, `license` | Имя, версия манифеста, описание, лицензия источника |
| `reader`, `source` | `tatoeba` или `stackexchange`; файлы кэша данных через запятую (`tatoeba/rus_sentences.tsv.bz2,tatoeba/eng_sentences.tsv.bz2`) |
| `sampling` | `token` — текст как написан. `type` — список слов, каждое один раз: так строятся наборы классов («Наборы классов»); у корпусного читателя `type` — ошибка |
| `layoutSets` | Пары раскладок: одна латинская (`ABC`), одна кириллическая. Предложение попадает в пару по хэшу ссылки |
| `scenarios` | Из `clean.cold`, `clean.warm`, `slip.cold`, `slip.warm`, `stuck`, `clean.toggle` |
| `epoch`, `seed` | Номер выборки и зерно. Порядок единиц задаёт `seed + epoch` |
| `tiers` | `{"ci":N,"full":M}` — сколько токенов измеряемой части брать на каждый сценарий |
| `split` | `{"dev":20,"by":"unit"}` — доля части `dev` в процентах |
| `filter` | `minTokens`, `maxTokens`, `requireScripts` (`cyrillic`, `latin`) |
| `normalize` | `keyboard` (умолчание): « » “ ” „ → `"`, ‘ ’ ʼ → `'`, — – → `-`, … → `...`, неразрывный пробел → пробел. Раскладки печатают только эти знаки без ⌥; без свёртки большая часть русских предложений с тире непечатна. `none` — как написано |
| `transform` | `lowercase`, `stripPunctuation` (без знаков, кроме `'` и `-` внутри слова): строка чата |
| `balance` | При нескольких файлах источника — столько единиц от каждого, сколько в самом малом; `false` отключает. По умолчанию `true` |
| `settings`, `end`, `fold`, `tags` | Пресет настроек случая (`default`); конец случая `space` (умолчание), `return`, `none`; свёртки; метки случая |

**Читатели.** Tatoeba: `id`, язык, текст через табуляцию из `.bz2`; ссылка
`tatoeba:<язык>#<id>`. Stack Exchange: `Posts.xml` из `.7z`, читает системный
`tar`; ссылка `post:<Id>#<n>`, `n` — номер предложения в посте. Оба читают
потоком по строкам: дамп в гигабайт целиком в память не попадает. Пост:
`<pre>…</pre>` вырезается целиком; `<code>…</code>` в строке остаётся, его
токены получают метку `code`; блочные теги (`p`, `br`, `li`, `blockquote`,
`h1`–`h6`…) делят абзацы, остальные теги исчезают без пробела; сущности
раскрываются. Единица — предложение. Предложение кончается на `.`, `!`, `?`
(и закрывающих знаках после них), за которыми идут пробел и заглавная буква
или цифра. Одна буква перед точкой («т. д.», «А. С.») — сокращение, не конец.

**Токены.** Токен режется на отрезки одного письма; знаки и цифры идут с
отрезком перед ними, знаки перед первой буквой — с первым отрезком.
«USB-порт» — `USB-` и `порт`, метка токена `mixed-token`. Язык токена — по
первой букве: кириллица — язык кириллической раскладки пары (`ru`, `uk`,
`be`, `kk`), латиница — `en`, нет букв — `-`. Токен без букв целится в
раскладку токена перед ним, первые такие токены — в раскладку первого токена
с буквами. Предложение с буквой другого письма или с символом, который
раскладка пары печатает только с ⌥ или Caps Lock, в набор не попадает.

**Сценарии.** Пальцы целятся в раскладки `X₀`, `X₁`… по токенам.

| Сценарий | Старт | Выбор раскладки в шагах | `warmup` |
|---|---|---|---|
| `clean.cold` | `X₀` | `layout` перед каждой сменой цели | нет |
| `clean.warm` | раскладка `warmup` | то же, включая первый шаг | предложение другого письма, набранное верно |
| `slip.cold` | вторая раскладка пары | `layout` на сменах цели, кроме первого шага | нет |
| `slip.warm` | раскладка `warmup` | как у `slip.cold` | то же, что у `clean.warm` |
| `stuck` | `X₀` | нет | нет |
| `clean.toggle` | `X₀` | `hotkey switchLayout` на сменах цели | нет |

`stuck` и `clean.toggle` строятся только для предложения с обоими письмами.
У одноязычного они равны `clean.cold`; такие случаи сборщик не строит и
считает под причиной `singleScript`. `warmup` — короткое (3–8 токенов)
предложение из того же источника в одном письме, противоположном письму
первого токена; его выбирает хэш ссылки из первых 2000 по порядку выборки.
`want` — `warmup`, пробел и токены. `err` ставит прогон Null: `layout` у
токенов, которые Null напечатал неверно, иначе `none`. Если в `clean.*` Null
ошибся, случай не строится (причина `nullWrongInClean`): ошибка набора там —
признак бага сборщика, а не человека.

**Выборка.** Первый проход читает весь источник и для каждой единицы считает
ранг: первое число `SplitMix64` с зерном `FNV-1a 64 (ссылка) ⊕ (seed +
epoch) · 0x9E3779B97F4A7C15`. Он хранит первые по рангу `4 · tier` единиц на
файл источника и ничего не разбирает. Файлы источника берутся по очереди, и от каждого
берётся столько единиц, сколько в самом малом файле (`balance`, по умолчанию
`true`): без этого малый файл (Tatoeba `kaz`) кончался бы, и остаток набора
был бы английским. Второй проход разбирает единицы по порядку, пропускает дубли
текста и строит сценарии, пока в каждом сценарии не наберётся токенов по
уровню. Разобранные единицы — случайная выборка источника, поэтому доли
причин отброса в `build.json` описывают источник. Новая эпоха берёт другой
порядок; единицы соседних эпох могут совпасть.

**Части.** `dev`, если `FNV-1a 64 (набор + U+001F + ссылка) mod 100 <
split.dev`. Все сценарии предложения лежат в одной части.

**Команда `cases build`** пишет `<out>/<набор>.jsonl` (умолчание
`.build/quality/cases/<уровень>/`) и `build.json`. В `build.json` по набору:
единицы источника, отобранные, разобранные, причины отброса, случаи, токены
и ошибки раскладки по сценариям, размер пула `warmup`, нехватка токенов
(`shortfall`) и SHA-256 файла. Слов в `build.json` и на экране нет. Тот же
вызов даёт те же байты.
С `--skip-missing` набор, чьего источника нет в кэше, не строится: строка
«пропущен: нет источника X» говорит об этом, остальные наборы строятся. Без
флага отсутствие источника — ошибка.

| Причина (`drops`) | Что значит |
|---|---|
| `tooShort`, `tooLong` | Токенов меньше `minTokens` или больше `maxTokens` |
| `noLetters`, `otherScript` | Нет букв; буква письма, для которого нет раскладки |
| `missingScript` | Нет буквы письма из `requireScripts` |
| `unprintable` | Символ, который раскладка пары печатает только с ⌥ или Caps Lock, или не печатает |
| `duplicate` | Тот же текст уже взят |
| `entity` | В тексте осталась именованная сущность (`&euro;`), которой читатель не знает: он читает пять XML, `nbsp laquo raquo mdash ndash hellip` и числовые |
| `singleScript`, `noWarmup`, `nullWrongInClean` | Причины по сценарию, см. выше |

## Наборы классов

Корпусный набор берёт текст, как его написали люди. Набор класса берёт **слова
одного вида** и проверяет, что с ними делает Perekey: слова из одной-двух букв,
слова, которые в другой раскладке тоже слова, сленг, команды, пароли. Класс —
это **правило над словарём, корпусом или генератором**; список слов в
`eval/classes/` только затравка (правило 1.5 плана: чиним классом, а не
списком). Манифест тот же (`eval/suites/<набор>.suite.json`), но `reader` —
`class`, `sampling` — `type`, а правило лежит в объекте `class`.

| Поле `class` | Смысл |
|---|---|
| `rule` | Правило из таблицы ниже |
| `languages` | Языки слов: `en` и кириллический язык пары раскладок (`ru` или `uk`). Язык вне пар манифеста — ошибка сборки |
| `minZipf`, `maxLetters`, `top` | Порог частоты, длина слова, число самых частых слов; у каждого правила свои умолчания |
| `minPerMillion` | Сколько раз на миллион токенов корпуса слово встречается, чтобы войти в набор |
| `corpus`, `corpusFull` | Файлы кэша данных, которые читает правило. `corpusFull` читается на уровне `full`, если файлы есть в кэше |

**Единица, вес, часть.** Единица — слово (у `numbers`, `cli` и `url` может быть
несколько токенов), ключ — слово в нижнем регистре с «ё» как «е». Все
написания одного слова («if», «If») — разные единицы одной части. Часть —
`FNV-1a 64 (набор + U+001F + ключ) mod 100 < 50`: у наборов классов доли
50 на 50 (РЕ8). Вес токена `w` — `10^(Zipf − 3)`: слово «где» весит больше
редкого. Слово, взятое из корпуса, весит столько, сколько раз оно
встретилось на миллион токенов; генератор и затравка без частоты — по
`unknownZipf` (2, то есть 0,1). Запасные числа правил — в `ClassRules.Options` с пометкой, откуда они. Отчёт печатает числа и без веса, и с весом
(`В` и `П` с весом — отдельная таблица).

**Затравка.** `eval/classes/<файл>.txt`: слово в строке, `#` начинает
комментарий, после табуляции — группа. Слово затравки входит в набор всегда
(уровень его не режет), слово группы пробы `probe/items.tsv` несёт метку
`seed:<группа>`. Если правило само нашло слово затравки, его вес — вес
правила. Сборка пишет в `build.json` (`classes`) число слов, найденных
правилом, число слов затравки и сколько из них правило нашло само: если
правило не находит свою затравку, оно описывает не тот класс.

**Уровни.** `tiers.ci` и `tiers.full` — наибольшее число слов правила на
сценарий (слов затравки сверх этого числа). Если слов больше, остаются самые
весомые; между равными решает порядок `seed + epoch`. Класс — перечисление,
а не выборка, поэтому новая эпоха меняет только то, какие слова оставил
предел, и не пересдаёт `dev` и `test` заново.

**Сценарии** — `clean.cold`, `clean.warm`, `slip.cold`, `slip.warm`, как у
корпусных наборов; `stuck` и `clean.toggle` для одного слова не строятся
(в нём нет второго письма). Единица без букв («15:30») целится в латинскую
раскладку пары или, у `numbers`, по метке, в кириллическую.

**Пара en ↔ uk** — те же правила с другими манифестами: `class.short.uk`,
`class.collision.uk`, … отличаются от русских названием, `languages`,
`layoutSets` (`ABC` + `Ukrainian-PC`), `source` (Tatoeba `ukr`) и файлами
корпуса. Кода для украинского нет; тест `theUkrainianPairIsMadeOfManifestsAlone`
держит это: у пары то же правило, те же сценарии и уровни. Без украинской
пары остались `class.translit` (схема ГОСТ — русская) и `class.code`.

**Источники.** Группы `scripts/fetch-data.sh`: `bench` (tldr-pages и шесть
репозиториев, закреплены SHA-256, ~5 МБ), `heavy` (ru.stackoverflow.com для
`class.oov` и `class.brands`; на CI его нет, и эти два набора там не строятся).
Имена Wikidata — снимок в репозитории `eval/classes/names.wikidata.tsv` (CC0,
дата и запрос в шапке); обновляет его вручную `scripts/wikidata-names.sh`,
скрипт загрузки их не берёт: ответ службы запросов меняется от запроса к
запросу. Лицензии — в `data/SOURCES.md`. Нет файла правила — ошибка сборки с
командой, которая его скачает.

**Хэш архива GitHub сменился.** Архивы репозиториев берутся с
`codeload.github.com` по ревизии. GitHub не обещает одинаковых байт, поэтому
`fetch-data.sh bench` остановится на «hash mismatch for code/…» с
хэшем скачанного. Что делать: сверить, что ревизия та же и файлы в архиве те же
(`tar -tzf` против прежнего списка), и поставить новый хэш в `fetch-data.sh`
**отдельным PR** — число наборов `class.code` не должно меняться вместе с
чем-либо ещё.

**Охват затравки `class.oov`.** Правило с порогом 20 на миллион находит из 90
слов затравки (сленг и жаргон пробы) лишь несколько: на ci 7, на ru.stackoverflow
целиком — см. отчёт этапа. Причина — нет `social.ru`: сленг живёт в
разговорном тексте, а не в вопросах о программировании. Порог не менялся;
затравка остаётся в наборе и даёт числа, которые сверяются с пробой.

**Чего эти наборы не меряют.** Слово стоит одно: контекста «за» (слова
того же языка перед ним) нет, он у `warm` всегда «против», как у
пробы `other3`; `own3` не строится. Слово из одной буквы в `class.short`
включает однобуквенные слова, которых нет в языке («s», «t» в словаре SCOWL
есть); частота у них мала и вес мал, число без веса от них разбавлено.
Пароль «Ghbdtn123!» без поля пароля — слово в строке, и Perekey вправе
счесть его раскладкой (поле пароля закрывает Secure Input, шаг
`secureInput`).

## Наборы правок слова

Набор правок слова проверяет не раскладку, а исправления слова на границе
(`docs/corrections.md`): опечатки, «ё», дефис, двойные заглавные, нечаянный
Caps Lock, аббревиатуры. Манифест тот же, плюс поле `correction`:
`{"kind": …, "weights": …}`. Человек целится в одну раскладку предложения и
не ошибается в ней: единственная ошибка случая — правка слова. `err` токена
ставит прогон Null, как у раскладки: `typo`, `yo`, `hyphen`, `doublecap`,
`caps`, `abbrev` у токенов, которые Null напечатал неверно, иначе `none`.
Пресет настроек — `all`, у `typos.none` — `default`. Исхода `disputed` в этих
наборах нет (раздел «Спорно и тихо»): задуманное известно точно.

| Набор (`kind`) | Сценарии | Что печатают пальцы | Читатель, источник |
|---|---|---|---|
| `typos.synth.equal`, `.neighbor`, `.swap` (`typo.synth`) | `fix` | В одном слове предложения (четыре буквы и больше) одна опечатка: соседняя клавиша, перестановка, пропуск, удвоение, лишняя буква. Доли видов правок в `weights`, в процентах | Tatoeba `rus`, `eng` |
| `typos.none` | `clean.cold` | Предложение как написано, пресет `default`: вред корректора опечаток на верном тексте | Tatoeba `rus`, `eng` |
| `typos.real.en` (`typo.real`) | `fix` | Настоящая описка из списка Википедии в предложении Tatoeba с тем же словом; нет предложения — слово отдельно (метка `alone`) | `misspellings`: `wikipedia-misspellings/for-machines.txt` (группа `bench`), `carrier` — Tatoeba `eng` |
| `typos.real.ru` (`typo.real`), каталог `eval/local/` | `fix` | Описки из файла, который положил человек | `typopairs`: `local/typos.real.ru.tsv` в кэше данных. Набор только локальный, метка `local` |
| `yo` | `fix` | Каждая «ё» набрана как «е». У слов с «ё» `err: yo`; слова с «е» без «ё» стоят как есть, и «ё» в них — вред | Tatoeba `rus`, предложения с «ё» |
| `hyphen` | `fix.merged`, `fix.spaced`, `keep` | Слово с одним дефисом между буквами набрано слитно, через пробел и как написано (`keep` — вред шага на верном тексте) | Tatoeba `rus`, предложения с дефисом |
| `doublecap` | `fix`, `keep` | `fix`: слово с заглавной и тремя буквами и больше набрано с двумя заглавными («ПРивет»), одно на предложение, метка `initial` или `inside`. `keep`: слова, у которых две заглавные настоящие (ГОСТ, USA, McDonald, iPhone), как есть, метка `capitals` | Tatoeba `rus`, `eng` |
| `capslock` | `fix` | Шаг `capsLock` и предложение: Shift нажат на первой букве, остальные идут заглавными. Подходят предложения, где первое слово — слово с заглавной и двумя буквами и больше; метка `lead` у него | Tatoeba `rus`, `eng` |
| `abbrev` | `fix`, `keep` | `fix`: аббревиатура (две–пять заглавных) набрана строчными. Предложение, где есть слово заглавными длиннее пяти букв, не берётся: это крик, а не аббревиатура. `keep`: она же заглавными | Tatoeba `rus`, `eng` |

**Опечатки.** Позиция, вид правки и замена буквы берутся из `SplitMix64` с
зерном от ссылки предложения и `seed + epoch`. Соседние клавиши — свои ряды
букв в `TypoMaker`, не копия геометрии корректора. Веса трёх наборов не равны
весам корректора (40 / 20 / 20 / 10 / 10): `equal` — по 20; `neighbor` — 70,
остальные 8 / 8 / 7 / 7; `swap` — перестановка 50, остальные 13 / 13 / 12 / 12.
Метка токена с опечаткой — вид правки (`neighbor`, `swap`, `drop`, `double`,
`stray`), по ней отчёт режет «починено» по видам. Опечатка, которая
оказалась настоящим словом, из набора не убирается: сборщику для этого нужен
лексикон, а сборка не должна зависеть от него. Такие опечатки Perekey не
исправляет (`TextCorrections.realWords` выключен), и они занижают «починено».

**Настоящие описки.** Берутся пары в одну правку (буква лишняя, пропущена,
другая, две соседние переставлены) и в одно слово: слово не короче четырёх
букв, исправление одно. Источник `misspellings` — «Lists of common
misspellings / For machines» (CC BY-SA 4.0), ревизия закреплена в
`scripts/fetch-data.sh`, формат `описка->слово`. Пары из файла человека
(`typopairs`): строка `описка<TAB>слово` или `предложение как набрано<TAB>предложение как
задумано`; строки с `#` — комментарии; в предложении должен отличаться
ровно один токен, на одну правку. Лицензии RUSpellRU и GitHubTypoCorpusRu
по первоисточнику не подтвердились (`data/SOURCES.md`), поэтому в репозитории
и в `fetch-data.sh` их нет. Манифест локального набора (`eval/local/typos.real.ru.suite.json`) лежит в репозитории без данных: файл с описками лежит только у человека, вне репозитория (правило 2.9), и это допустимо. Файл может иметь окончания строк `\r\n` и пробелы вокруг полей; `typopairs:N` в ссылке случая — номер строки файла, считая пустые; если больше 90 % строк не пары, сборка пишет предупреждение. Набор из такого файла собирают так:
`perekey-eval cases build --suites eval/local --cache <кэш> --only typos.real.ru`.

**Выборка.** Как у корпусных наборов: один проход по источнику, ранг по
`seed + epoch`, до `6 · tier` предложений на сценарий (в них только
предложения, где правка возможна), второй проход разбирает и строит. Для
`doublecap` и `abbrev` `balance` выключен: слов с настоящими двумя заглавными
в Tatoeba `rus` много меньше, чем в `eng`, и с `balance` русский остаток
обрезал бы английский.

| Причина (`drops`) | Что значит |
|---|---|
| `mixedScript` | В предложении оба письма: наборы правок печатают одну раскладку |
| `noTarget` | В предложении нечего менять (нет слова с «ё», дефисом, подходящей заглавной) |
| `noTypo` | Вид правки не подошёл слову (две одинаковые буквы при перестановке, нет соседней клавиши) |
| `nullRight` | После правки Null не ошибся ни в одном токене: случай ничего не меряет |

**Чего это не меряет.** «ПРИВЕТ» (Shift при включённом Caps Lock даёт
строчную букву в удалённом рабочем столе): на Mac клавиатура так не
печатает, `EvalDesk` тоже. Что Caps Lock выключен после правки, в случае не
проверяется: выключение видно по тому, что остальные слова вышли строчными, и
по `lead` у первого слова. У `capslock` в `err: caps` стоят все слова,
которые Null напечатал заглавными; после первой правки Caps Lock выключен, и
остальные слова «починены» тем же решением. Решение отдельно описывает метка
`lead`.

## Личные наборы

Набор из записи собственного набора человека. Источник — файлы `.pksession`
(`docs/classifier.md`, «Замер на живых сессиях»): их делает только сборка
разработчика, настоящих записей в репозитории нет. Метка из поведения —
то, что человек сделал после решения Perekey (`SessionWords.extract`), —
становится задуманным текстом. Сильная метка делает случай, слабая — нет.

```
export PEREKEY_EVAL_PRIVATE=~/perekey-private          # вне репозитория и вне scratchpad
perekey-eval cases personal <записи или каталоги> --model <каталог> [--name sessions]     # имя: a-z, 0-9, -, до 32 знаков
perekey-eval play --cases $PEREKEY_EVAL_PRIVATE/personal.sessions.jsonl --model <каталог> \
                  --out $PEREKEY_EVAL_PRIVATE/run-1
perekey-eval report $PEREKEY_EVAL_PRIVATE/run-1
```

`cases personal` проигрывает каждый сегмент записи точным повтором (`exact`)
с моделью из `--model` и пишет `personal.<имя>.jsonl` в каталог
`PEREKEY_EVAL_PRIVATE`. Модель должна быть той, что делала запись: слова
после первого ответа, не совпавшего с записанным, случаев не дают
(`afterMismatch`) — метка за ними не про это решение. Печатает только числа:
сегменты, слова по меткам, случаи по сценариям, причины, по которым случая
нет.

| Метка (сильная) | Случай | Сценарий |
|---|---|---|
| ложное переключение, неверная правка слова | слово как набрано, пальцы и раскладка одни: вред, если Perekey тронет | `clean.cold`, `clean.warm` |
| пропуск (слово оставлено, человек перенабрал его) | клавиши в раскладке, в которую человек перенабрал; без явной цели — в единственную другую раскладку записи | `slip.cold`, `slip.warm` |
| переключение, которое человек вернул сочетанием после Backspace | клавиши в раскладке переключения | `slip.cold`, `slip.warm` |

Остальное — слабые метки («человек печатает дальше») и неясные — случая не
даёт. Правка слова, возвращённая сочетанием, тоже: случай не умеет сказать,
чем было исправление. `warm` — слова перед проверяемым в одном фокусе и без
щелчка (до трёх, `SessionCases.Options.contextWords`) стоят в `warmup` так,
как человек их в итоге видел; цепочка рвётся на слове, итог которого
неизвестен. Слова из поля пароля, под Secure Input и при неизвестном фокусе
в `warmup` не попадают. `err` ставит прогон Null, как у корпусных наборов.
Набор — `personal.<имя>`, часть `dev`, теги из закрытого списка
(`SessionCases.allowedTags`): слово записи в тег не попадает.

**Приватность** (правило 2.9). Файл набора содержит слова человека — это
сам набор. Всё остальное — нет:

- Каталог `PEREKEY_EVAL_PRIVATE` лежит вне репозитория (выше нет `.git`) и
  вне `/private/tmp/claude-…` (scratchpad раздаётся наружу); иначе команды
  отказывают. Каталог 0700, файлы 0600, в каталоге `.metadata_never_index`
  (Spotlight).
- Набор `personal.*` читается только из файла внутри каталога, а файл внутри
  каталога держит только `personal.*`. Прогон такого набора пишется только
  внутри каталога (`play --out`, `report --out`, `diff --out`); `--out`
  внутри каталога требуется и тогда, когда сама папка прогона лежит в
  каталоге, хотя в `run.json` нет `personal`. Отчёт и `diff` личного прогона
  пишутся с правами 0600.
- Слова в `events.jsonl` и `words.tsv` — хэш `h:<12 hex>`: SHA-256 от соли
  каталога и слова. Соль — случайные 32 байта в `.salt` (0600), без неё хэш
  короткого слова подобрал бы словарь. Хэш слова один в разных прогонах
  одного каталога, поэтому `diff` и список слов работают. Так же с `id`:
  в файле набора это хэш содержимого случая (по нему слово подбирает
  словарь), в файлах и выводе прогона — `набор/сценарий/` и 12 hex соленого
  хэша; в сообщениях — он же или `(personal)`.
- Соль лежит в том же каталоге, рядом с данными: у кого есть каталог, тот
  подберёт хэши коротких слов. Каталог не класть в iCloud, Dropbox и папки
  резервных копий (Time Machine и подобные); кода, который это проверяет,
  нет. `.salt` неверной длины — ошибка, новая соль её не заменит: хэши
  прежних прогонов перестали бы совпадать. Соль создаётся эксклюзивным
  открытием, два одновременных запуска получают одну.
- Отчёт всех форматов, `diff`, `cases list`, `selfcheck`, сообщения об
  ошибках (проверки случая, чтения файла случая и записи, игры) не содержат
  слов набора: только числа, id (хэш содержимого) и хэши. `case` личный
  случай не показывает. Подробности ошибки чтения личного файла скрыты:
  сообщение разбора может цитировать значение. Это держится на личных путях
  (`cases personal`, любой аргумент внутри каталога): любая ошибка, кроме
  своей, печатается именем типа без значения.
- Имя набора `--name` — только `a-z`, `0-9`, `-`, до 32 знаков; иначе отказ
  без самого имени.
- В `run.json` стоит `personal: true`.

Тест (`PersonalPrivacyTests`) собирает набор из синтетической записи, играет
его на машине и на Null, строит отчёты четырёх форматов и `diff`, запускает
`cases check|list`, `case`, `selfcheck` с перехватом вывода и ищет в каждом
файле и в stdout и stderr каждое слово набора, то, что напечатал Null, и то,
что сделала машина. Контрольный прогон тех же случаев не как личных слова
находит.

## Обучение

Наборы `learning.*` меряют, как Perekey учится на отменах (`docs/classifier.md`,
«Обучение»). Это не случаи формата v1: у обучения есть состояние между
днями (`WordRules`), а человек читает текст и отвечает на него. Формат
случая, исходы и счётчик не менялись; у обучения свои файлы и свои метрики.

```
словарь ─► день, сообщение, слово по Ципфу ─► наборщик ─► EvalDesk (InputMachine)
              ▲                                              │ текст поля, undoSettled, перенаборы
              │                                              ▼
   WordRules ◄─ count / answer / unlearn ◄─ реактор (смотрит на текст и отвечает)
       │
       └─► settingsChanged (выученные слова → исключения) ─► машина
```

**Набор** — манифест `eval/learning/<имя>.json` (имя начинается с `learning.`,
чтение строгое: лишний ключ — ошибка) и словарь `eval/learning/<имя>.tsv`.

| Поле | Смысл |
|---|---|
| `name`, `about`, `vocabulary` | имя набора, описание, файл словаря рядом с манифестом |
| `layouts` | ровно две раскладки в системном порядке: слово и его другое прочтение |
| `settings`, `apps` | пресет (`default`) и программы, между которыми человек переключается по сообщениям (`com.apple.TextEdit`) |
| `days`, `messagesPerDay`, `wordsPerMessage` | число «дней», сообщений в день, слов в сообщении (1) |
| `zipf` | показатель закона Ципфа по порядку слов в файле: вес слова `1/номер^zipf` |
| `meantOther` | доля появлений, где человек хочет другое прочтение (те же клавиши, но переключение верно) |
| `backspaceShare` | доля отмен неверной поправки, которые человек делает Backspace; остальные — кнопкой «Отменить» |
| `accident`, `accidentContinues`, `accidentRetypes` | доля верных поправок, за которыми идёт «случайный Backspace ради знака»; доли исходов такого Backspace (ниже) |
| `answer` | политика ответа на вопрос «Больше не менять…»: `everywhere` («Везде»), `here` («Только здесь»), `never` (не отвечает, слово остаётся кандидатом) |
| `reaction` | секунд от конца слова до ответа человека (0,5) |
| `seed` | зерно `SplitMix64`; число прогонов `--seeds N` берёт зёрна `seed … seed+N−1` |

Числа манифестов — модель человека, а не замер (данных нет). Каждое можно
качать в `learning sweep` (`manifest.<имя>`).

**Словарь.** `слово<TAB>раскладка<TAB>вредов`: слова, которые Perekey ложно
переключает, а человек хочет оставить. Другое прочтение стенд берёт сам
(`WordRules.readings`). `eval/learning/learning.personal.tsv` строит команда
`learning vocabulary` из события `harm` с формой `layout` в `events.jsonl`
прогона `play` на `main`: слово набрано как задумано (`err: none`),
сценарий `clean.*`, часть `dev` (части `test` в `events.jsonl` нет, правило
2.8). Отбор: только буквы, не короче двух; по числу вредов (убывание), потом
по алфавиту; первые 50. Раскладка — по языку токена: `en` — ABC, `ru` —
Russian. Команда и коммит прогона записаны в заголовке файла. Команда читает
`run.json` прогона и отказывает, если в нём `testRevealed: true` (слова части
`test` в `events.jsonl`) или `personal: true` (личный набор), и если `run.json`
нет: словарь уходит в репозиторий.

Словарь `learning.personal.tsv` собран так, на `main` `8645a66`:

```
perekey-eval cases build --tier ci --suites eval/suites --cache <кэш данных> --out .build/quality/cases --only <наборы>
perekey-eval play --cases .build/quality/cases --cases eval/cases --model .build/model --out .build/quality/runs/main \
                  --cache <кэш данных> --lexicon .build/quality
perekey-eval learning vocabulary --run .build/quality/runs/main --out eval/learning/learning.personal.tsv --size 50
```

`<наборы>` — все наборы уровня `ci`, для которых был источник в кэше; без
`class.brands*`, `class.oov*`, `tech.ruso` (нет архива ru.stackoverflow.com).
Поэтому словарь почти весь из коротких слов (`class.short`,
`class.collision`) и транслита: набранное прочтение у них часто слово модели
(`known`), и порог 1 почти всегда решает. Пересобрать словарь с полным кэшем —
команды те же; слова части `test` в него не попадут при любом кэше.

**Сообщение.** Сообщение — новое поле (`focus`), одно слово (или
`wordsPerMessage`) и Return. Человек ставит раскладку слова, набирает слово и
пробел, ждёт `reaction` и смотрит на текст поля. Слово «как задумано»,
если текст кончается им и пробелом. Возможны три ситуации, и реактор
(`Typist.Reactor`) отвечает на каждую:

| Что видит человек | Что делает |
|---|---|
| задумано и Perekey не трогал | ничего |
| задумано, Perekey поправил верно | ничего; с долей `accident` — Backspace ради знака (ниже) |
| не задумано, Perekey поправил (вред) | отмена: Backspace с долей `backspaceShare`, иначе кнопка «Отменить» |
| не задумано, Perekey оставил (пропуск) | `convertLastWord` |

Случайный Backspace — «jrtq » → «окей », Backspace, чтобы убрать пробел перед
запятой: Perekey отменяет поправку. Человек видит вернувшееся слово и делает
одно из трёх: ставит запятую (`punctuation`, по остатку долей: слово остаётся
как набрано, очков нет); идёт дальше (`accidentContinues`: слово осталось как
набрано, Backspace засчитан очком); перенабирает `convertLastWord`
(`accidentRetypes`, очков нет). Слово, оставшееся неверным в конце сообщения,
считается в `leftWrong`. Сам перенабор слова с запятой («jrtq,») стенд не
моделирует: `convertLastWord` перенабирает запятую как клавишу «б»
(«окейб»), и человек так не делает.

**Цикл обучения** — тот же, что у приложения (`InputController.countUndo`,
`answer`, `unlearn`), только ответ даёт политика:

1. `Effect.undoSettled` → `WordRules.count(report, at:, day:, readings:, options:)`.
2. Вопрос (`LearningStep.question`) → ответ по `answer` → `WordRules.answer`.
3. Слово выучено или забыто → снимок настроек (`AppSettings.snapshot`:
   исключения, исключения по программам) → `settingsChanged` в машину.
4. Перенабор `convertLastWord` (`EvalDesk.posted`, origin `manual`) →
   `WordRules.unlearn(typed:retyped:app:)` → снимок.

Время идёт по модельным часам: день — 86 400 с, между сообщениями 600 с,
номер дня `Int(время / 86 400)`, как в приложении. Порог отчёта машина считает с
умолчаниями `LearningOptions` (`CorrectionUndo`). Стенд пересчитывает порог
из `UndoFacts` теми же `LearningOptions.threshold(for:frequentRank:)`, поэтому
пороги можно качать. С умолчаниями пересчёт обязан совпасть с порогом
машины; не совпал — прогон падает (`drift`): значит, копия разошлась с ядром.

**Метрики** (на прогон; `learning run` печатает среднее по зёрнам).

| Метрика | Что считает |
|---|---|
| `harmed` | слова, которые человек хотел оставить, а Perekey поправил, до ответа человека |
| правок руками (`interventions`) | отмены (Backspace, кнопка) и перенаборы руками. День 1 и последний день — отдельно |
| вмешательств до тишины на слово (`interventionsToSilence`) | среднее **только по замолчавшим** словам: отмены слова, которое человек хотел оставить, за весь прогон, у слов с вредом, чьё последнее такое появление обошлось без отмены (`wordsSilent` из `wordsHarmed`). Слова, которые так и не замолчали, в среднее не входят; их число — `wordsNeverSilent` (`wordsHarmed − wordsSilent`), в отчёте «words that never went silent», в таблице точек столбец `neverSilent` |
| выучено (`learnedWords`) | слова, выученные хотя бы раз; `asked` — вопросов задано (слово, забытое перенабором и выученное снова, спрашивают снова) |
| ложно выучено (`falseLearned`) | слова, выученные впервые на очках случайных Backspace (`Word.learnedByAccident`): без очков, которые дали Backspace «ради пробела» с продолжением набора (`accidentContinues`), очков слова при вопросе было бы меньше порога. Очки считает стенд по разности очков кандидата `WordRules` до и после отмены; `Word.accidentPoints` — очки слова от случайных Backspace. Слово, выученное отменами руками, не ложное, даже если человек его потом не хотел оставить (для этого есть `learnedThenNeeded`). `falseLearnedPer1000Accidents` — на 1000 случайных Backspace |
| выучено и потом нужно исправить (`learnedThenNeeded`) | выученные слова, у которых потом было появление с другим прочтением (`neededAfterLearned`): Perekey слово не тронул, человек перенабрал руками |
| `oldRuleWouldLearn` | слова, которые правило до подсчёта очков (`LearningStep.OldRule.learn`) выучило бы первой же отменой |
| `leftWrong` | слова, оставшиеся неверными в конце сообщения |

Наборы репозитория: `learning.personal` (50 слов, человек хочет их оставить в
9 случаях из 10), `learning.control` (те же слова, человек всегда хочет другое
прочтение, много случайных Backspace: всё выученное тут выучено ложно),
`learning.jrtq` (случай «jrtq» из памяти `undo-learning-redesign`: одно слово,
каждый раз случайный Backspace и запятая; выучено должно быть 0). Тест
`theCommittedJrtqSetLearnsNothingBecauseOfItsRule` играет этот набор с
моделью, у которой «окей» есть в словаре: случайных Backspace больше 0, каждое
слово переключено, выучено 0 и очков 0, правило до подсчёта очков выучило бы
слово (`oldRuleWouldLearn` 1); и тот же набор с продолжением набора после
Backspace (`accidentContinues` 1) при пороге 1 слово выучивает. Ноль даёт
правило (Backspace перед знаком весит 0), а не устройство набора.

**Команды.** `learning run` играет наборы и печатает метрики; с `--out`
пишет `learning.json` (все прогоны, `commit`, хэши моделей, `--options`),
`days.tsv` и `words.tsv`; два прогона дают те же байты. `--options` берёт
поля `LearningOptions` и `Classifier.Options` в одном объекте:
`{"frequentThreshold":4,"threshold":12}`. `learning sweep --grid
'{"frequentThreshold":[2,3,4],"manifest.accidentContinues":[0,0.1]}'` играет
каждое сочетание на каждом наборе и печатает таблицу точек (`--out` — в
файл). Сетку команда проверяет до первого прогона: значение, которое поле не
примет (дробное число для порога, доля вне 0…1), и сочетание, которое
манифест отвергает (`accidentContinues` и `accidentRetypes` вместе больше 1),
останавливают её сразу, а не на последней точке. Таблица имён — `LearningOptionsTable`; тест падает, если в
`LearningOptions` появится поле, которого в ней нет. Пороги ядра этот
стенд не меняет, только меряет.

## Пакет случаев

Пакет — случаи наборов из источников с подтверждённой лицензией, собранные в один архив, чтобы любой
переключатель играл те же случаи без сборки из источников. Имя — константа `PackPolicy.packageName`
(`layoutbench-v1-e1`: формат случая 1, эпоха 1); имя, публикация ассетом выпуска и ссылка в `README`
остаются решением владельца (РЕ4). Пока оно не принято, пакет собирают только локально.

```
perekey-eval cases pack --tier ci --out <файл .tar.zst или каталог>
                        [--suites <каталог>] [--cache <каталог>] [--layouts <каталог>]
                        [--lexicon <каталог>] [--classes <каталог>] [--pack-dir eval/pack]
```

Команда собирает случаи каждого набора, который `PackPolicy.standard` кладёт в пакет, и пишет архив
`<имя>.tar.zst`, рядом `<имя>.tar.zst.sha256` (хэш архива) и `<имя>.tar.zst.tar.sha256` (хэш tar до сжатия; внутрь
tar его положить нельзя). Печатает оба хэша и версию `zstd`. SHA-256 tar не зависит от версии `zstd`; SHA-256
архива зависит (уровень 19, один поток); версия записана в `README.md` пакета (`{{zstd}}` шаблона) и печатается
командой. `zstd -dc <имя>.tar.zst | shasum -a 256` даёт хэш tar. Нужен `zstd` в `PATH` (`brew install zstd`).
Уровень один, `ci` (`--tier full` — ошибка), `--only` и `--epoch` не принимаются: пакет — вся эпоха своих наборов.

```
<имя>/
  cases/<набор>.jsonl    случаи, как их пишет `cases build`
  pack.json              счётчики и SHA-256 наборов (как `build.json`), лицензия манифеста каждого набора,
                         SHA-256 каждого файла источников и каждой раскладки, число случаев Stack Exchange
                         по лицензии поста (`stackExchangeCases`)
  ATTRIBUTION.md         источники, лицензии, как найти авторов (из `PackPolicy`)
  attribution-se.tsv     строка на каждый пост Stack Exchange, на который ссылаются случаи: номер, тип, сайт,
                         ссылка, автор, лицензия поста (только в пакете с такими постами)
  LICENSE                CC BY-SA 4.0, текст лицензии (`eval/pack/LICENSE`); для нашей разметки, не для текста источников
  README.md              формат случая, исходы, как играть (`eval/pack/README.md`)
```

**Лицензия по источнику, а не по имени набора.** Текст каждого случая — под лицензией своего источника, а не под
одной лицензией на весь пакет. `PackPolicy` сверяет каждый файл, который читает набор (`source`, `carrier`, файлы
корпуса правила класса, а после сборки — файлы, которые правило прочитало), с префиксами папок источников, названных
в записи набора (`PackSource.pathPrefixes`). Файл вне этих префиксов — ошибка (код 2), пакет не собирается и список
файлов назван. Новый источник в манифесте набора не пролезет в пакет под именем набора, который уже разрешён.

**Stack Exchange.** `attribution-se.tsv` — таблица по постам (колонки `post_id`, `type`, `site`, `url`, `author`,
`license`). Автор — отображаемое имя из дампа (`OwnerDisplayName`) или `user:<OwnerUserId>`; если в дампе нет ни
того ни другого, пакет не собирается. Лицензия — `ContentLicense` дампа; у поста без неё — по дате по правилу
Stack Exchange (до 2011-04-08 — CC BY-SA 2.5, до 2018-05-02 — 3.0, позже — 4.0). Фильтра «только 4.0» нет: это часть
решения РЕ4. Число случаев по лицензиям печатает команда и пишет `pack.json`.

**Что в пакете.** Наборы шага `ci` из `scripts/quality.sh` (`CI_SUITES`) без `class.code`. Тест держит равенство:
набор в списке скрипта и не в пакете — красный тест. Остальные манифесты `eval/suites` оставлены вне пакета с
причиной в `PackPolicy.excluded`; манифест без решения — красный тест (`PackTests`).

| Вне пакета | Почему |
|---|---|
| `class.code` | Текст — код шести репозиториев (Apache-2.0, MIT, PostgreSQL License). `data/SOURCES.md` не пускает его в публичный пакет |
| `tech.ruso`, `class.oov`, `class.brands` и их `.uk` | Читают `ru.stackoverflow.com` (группа `heavy`, гигабайт); не входят в уровень `ci` |
| `abbrev`, `capslock`, `prose.be`, `prose.kk`, `class.caps`, `class.punct`, `class.translit` и все `class.*.uk`, `protect.*.uk` | Строятся только на `full` |
| `social.ru` (набор не построен), `typos.real.ru` (локальный) | Лицензия источника не подтвердилась (`data/SOURCES.md`, «Настоящие описки»; отчёт E2 о Taiga). В `eval/suites` манифеста нет |
| `flow.*`, `incidents` | Случаи, написанные руками, лежат в `eval/cases` репозитория под его лицензией. Решение о лицензии пакета — владельца |
| `personal.*`, `learning.*` | Личные и обучающие наборы не идут в пакет никогда (`PackPolicy.problems`) |

Источник без подтверждённой лицензии (правило 2.5) нельзя ни добавить в пакет, ни оставить в нём «до выяснения»:
набор вне `PackPolicy.entries` в пакет не попадёт. Источник, которого нет в кэше, останавливает команду (код 2),
а не уменьшает пакет молча: пакет без набора был бы другим пакетом под тем же именем.

**Воспроизводимость.** Архив — детерминированный tar (`TarArchive`: пути по байтам, владелец 0, права 0644, время 0,
без имён) со сжатием `zstd -19 -T1`. Одни и те же файлы источников дают одни и те же байты; два запуска подряд
дают одинаковый SHA-256 (тест `thePackBuildsTwiceWithTheSameHash`). Источники Tatoeba не закреплены (скрипт
записывает их хэш в `MANIFEST.sha256`): другой снимок Tatoeba даёт другой пакет, и `pack.json` называет хэш снимка.

**Играть.** `tar -xf <имя>.tar.zst`, затем `perekey-eval play --cases <имя>/cases --model <каталог> --layouts <раскладки> --out <прогон>`.
`play` без `--cache` и `--lexicon` не читает источников; без лексикона нет меток `disputed`, `silent` и признаков
`known`, `zipf`, `collision`, `seen` (раздел «Лексикон»). Тест `aPlayedPackNeedsNeitherTheSourcesNorTheirCache`
играет пакет после удаления кэша.

## Настоящая программа

Испытуемый **App** — настоящий Perekey в настоящей программе. `perekey-e2e play`
берёт те же события наборщика, что и `Machine`, шлёт их `CGEvent`-ами в
TextEdit с темпом случая и читает текст поля через Accessibility. Счёт тот же:
по итоговому тексту (правило 2.7). Только локально: нужен вошедший пользователь,
Accessibility у терминала и работающий Perekey.

```
perekey-e2e play --cases <файлы или каталог> --app TextEdit --out <каталог прогона>
                 [--only <набор,...>] [--split dev|test|all] [--limit N] [--reveal-test] [--dry-run]
```

`--dry-run` ничего не шлёт, не трогает программу и не создаёт файлов: печатает,
сколько случаев играется, сколько нет и почему, сколько минут займёт набор и
пустит ли охрана (см. ниже) прямо сейчас. Код: `Sources/PerekeyEvalKit/App/`
(вся логика, с тестами `AppSystemTests`) и `Sources/perekey-e2e/MacPlatform.swift`
(то, что говорит с системой: `CGEvent`, AX, раскладки; тестами не покрыт).

### Охрана ввода

Заблокированный экран отправляет `CGEvent` в поле пароля окна входа. Человек за
клавиатурой получил бы чужие клавиши в свою работу. Поэтому `InputGuard`
проверяет **перед каждым событием** (не только перед случаем), и ни одна
клавиша не уходит, пока проверка не пройдена:

| Проверка | Условие отказа | Код выхода |
|---|---|---|
| Экран | `CGSessionCopyCurrentDictionary()["CGSSessionScreenIsLocked"]`; нет сессии или она не на консоли — тоже отказ | 3 |
| Человек | `HIDIdleTime` (`IOHIDSystem`) меньше 10 с перед первой клавишей. Дальше свои клавиши тоже обнуляют `HIDIdleTime`, поэтому проверка другая: простой должен быть не меньше времени с последней своей клавиши (минус 1 с — свои часы и поздний перенабор Perekey). Меньше — после нашей клавиши кто-то нажал клавишу или двинул мышь. Машина не отвечает — отказ | 4 |
| Программа | Впереди не та программа (`--app`) | 5 |

Отказ посреди прогона оставляет записанное: файлы прогона из сыгранных случаев
и `app.json` с причиной в `aborted`. Числа охраны — в `InputGuard.Options`:
10 с и 1 с — догадка, а не замер. Слишком малая «уступка» остановит хороший
прогон (безопасно), слишком большая позже заметит человека. Дырка: человек,
тронувший мышь во время пауз короче «уступки», охране не виден до следующей
паузы.

### Что играется

Не играются, а считаются в `app.json` (`skipped`) по причине:

| Причина | Что в случае |
|---|---|
| `focus`, `mode`, `secureInput` | шаги `focus`, `mode`, `secureInput`: программа их не принимает |
| `capsLock` | шаг `capsLock`: состояние клавиши не поставить событием |
| `undo`, `hint` | кнопка «Отменить» и щелчок по подсказке: это окно самого Perekey |
| `checks` | проверки `corrections` и `undone`: счёта правок у программы нет. `layout` проверяется |
| `app`, `settings`, `exceptions`, `prior` | `env`: программа играет с настройками, которые стоят у неё. Пресет `default`, режим `auto`, без исключений |
| `layouts` | раскладки случая не равны включённым в системе |

Щелчки `start`, `end` и позиция идут клавишами (⌘↑, ⌘↓, →): мышь стенд не двигает.
Выделение — ⇧←.

### Перед прогоном и после

1. Включить в системе ровно раскладки случаев (`ABC`, `Russian`).
2. В Perekey: настройки по умолчанию (Shift переключает раскладку, Option
   перенабирает), режим «Авто». Исключения и выученные слова очистить:
   каждый случай начинается без них.
3. TextEdit: открыть пустой документ, формат «Простой текст». Правка →
   Подстановки и Орфография: умные кавычки, тире, автоисправление выключить.
4. Терминал: Accessibility и право слать события (`perekey-e2e check` — код 0).
5. Не трогать клавиатуру и мышь; экран не блокировать, не давать ему гаснуть.

Перед случаем драйвер: переводит фокус в Finder и обратно (Perekey забывает слова
прошлого случая, как у нового поля стенда), очищает поле через AX (клавиш нет),
шлёт Escape (конец слова в буфере Perekey), выбирает стартовую раскладку и
ждёт, пока система её подтвердит. Не подтвердила за 2 с — ошибка, а не пропуск.

### Файлы

Прогон пишет файлы любого прогона (`system` в `run.json` — `app`) и `app.json`:
программа, пропущенные случаи по причинам, и по каждому сыгранному случаю `id`,
часть, раскладка в конце, SHA-256 текста и сам текст (для части `test` текст
только с `--reveal-test`, правило 2.8).

### Набор `fidelity` и отчёт

План 12.4: 300 случаев, по 20 из каждого `flow.*` и 100 из `tech.ruso`. Числа —
в `FidelitySet.Options`. Выбор детерминирован: в каждом наборе берутся случаи с
наименьшими хэшами содержимого (последние 12 hex id).

```
perekey-eval cases fidelity eval/cases .build/quality/cases/ci --out .build/quality/fidelity.jsonl
perekey-e2e play --cases .build/quality/fidelity.jsonl --app TextEdit --out .build/quality/run-app
perekey-eval fidelity --cases .build/quality/fidelity.jsonl --app-run .build/quality/run-app \
    --model .build/model --format md --out .build/quality/fidelity.md
```

Отчёт сыгрывает Machine на тех же случаях, что сыграла программа, и сравнивает
итоговый текст. Доля — расхождения по тексту на сыгранные случаи; цель ≤ 1 %.
Случаи, что программа не играет, в знаменатель не входят и перечислены по
причинам. Расхождение только в раскладке в конце — в списке, но не в доле.
Слова части `test` в отчёте скрыты (`--reveal-test` показывает). Каждое
расхождение — либо правка стенда, либо строка в «Чего стенд не моделирует».

### Прогон с другим переключателем (протокол)

Сам прогон — только по слову Николая; результат не публикуется без него (РЕ5).
Протокол:

1. Записать версию каждого переключателя: имя, версия (`About`), путь, `codesign -dv`, дата,
   версия macOS. В отчёте — рядом с числами.
2. Остановить Perekey (`Выйти` в меню; `pgrep -x Perekey` пуст) и любой другой
   переключатель раскладки или исправитель (Punto Switcher и подобные). Одновременно работает один.
3. Запустить проверяемый переключатель, настройки — по умолчанию программы, горячие клавиши
   записать. Если горячая клавиша переключения не Shift, случаи с `hotkey` пропустить: они
   предполагают привязки Perekey.
4. Включить в системе те же раскладки. Выполнить «Перед прогоном и после».
5. Сыграть тот же `fidelity.jsonl` (или другой набор) командой `perekey-e2e play … --out
   <каталог>`; `--app` тот же. Прогон идёт тем же кодом: `run.json` не знает, чей это
   переключатель, поэтому имя и версию записать в имя каталога и в отчёт.
6. Сравнить прогоны `perekey-eval diff <каталог Perekey> <каталог другого>`.
7. Вернуть всё как было: остановить чужой переключатель, запустить Perekey.

Что протокол не проверяет: что чужой переключатель не пишет в журнал и не отправляет
текст наружу. Это решает человек до прогона. «Чистая комната» (`docs/PLAN.md`):
изучается поведение, чужой код не читается.

## Чего стенд не моделирует

- **Проверка каретки строже настоящей.** Стенд сравнивает текст поля
  точно. Настоящий `CaretCheck` видит то, что даёт AX: автоскобки и
  предиктивный ввод программы, ответ «не знаю» и таймаут AX, после которых
  перенабор идёт без сверки.
- **Перенабор через AX** (`Retype.viaAccessibility`) и его отказ: стенд
  всегда печатает перенабор клавишами.
- **`ReplayGate`**: в стенде повторы всегда возвращаются и сразу, порядка
  ожидания повторов в `PerekeyInput` и их потери нет.
- **Кнопка «Отменить» без `HintLifetime`**: подсказка в стенде живёт, пока
  её правка последняя; срок показа (3 с, следующее слово) не учитывается.
  `HintLifetime` лежит в слое программы, а `PerekeyDesk` зависит только от
  ядра.
- **Сроки по модельному времени**: стенд догоняет по правилу отставания,
  срок ограды наступает по часам наборщика, а не по настоящим таймерам;
  настоящей задержки AX и программы нет.
- Автодополнение и автозамену программ.
- Подсказку: её вид и срок показа. Вопрос «Только здесь / Везде / Нет»
  стенд знает только как политику ответа (`learning.*`); срок вопроса
  (8 с без набора), закрытую без ответа подсказку и панель «Слова» он не
  моделирует. В `learning.*` вопрос всегда получает ответ сразу, а
  `never` — никогда.
- Обучение на отменах между случаями формата v1: машина шлёт `undoSettled`, а
  список исключений пополняет программа. Каждый случай начинается с пресета.
  Обучение по дням меряют только наборы `learning.*` (раздел «Обучение»).
- Человека в `learning.*`: все доли манифестов — догадка, не замер. Журнал
  обучения (`LearningJournal`) в стенде не пишется.
- Пороги `TypoCorrector` из командной строки.
- Настоящие описки из Википедии русского языка и из размеченных корпусов
  (RUSpellRU, GitHubTypoCorpusRu): лицензии не подтверждены, набор
  собирается только из файла человека. «Ё» и дефис берутся из Tatoeba:
  шарда Википедии (формат parquet) читатель наборов не читает.
- Опечатки, где неверное написание — настоящее слово (`realWords` выключен).
- Личный набор в точности как человек: настройки записи (исключения,
  выученные слова) в случай не переходят, он играется с пресетом `default`;
  слово кончается пробелом, каким его кончил человек — неизвестно.

Это закрывает испытуемый App — настоящая программа (раздел «Настоящая программа»): что из этого
программа делает иначе, показывает отчёт `fidelity`. Сам App стенд тоже не моделирует: щелчок
мышью он заменяет клавишами, а Caps Lock, фокус, режим, Secure Input и кнопку подсказки не играет.

## История определений

| Версия | Что |
|---|---|
| случай v1, счётчик 1 | Первая версия: формат, шаги, исходы и метрики этого документа (PR #17, первые коммиты) |
| счётчик 2 | Правило склейки только сопоставляет токены: группа верна лишь при равенстве текста по свёрткам или `accept` («во первых» при «во-первых» неверно). Лишний токен после слияния делает неверными оба токена группы. `checks` вынесены из счётчика в метку случая: `exact` у `scoring: case` — только текст |
| счётчик 3 | Исход `disputed` (7.5): вред на корпусном наборе, где машина исправила опечатку источника, не вред (при лексиконе; без лексикона исходов не меняется). Метка `silent`. Признак `tags` — теги случая и токена. `summary.json` схема 2; `play` пишет ещё `counts.tsv`, `slices.json`, `words.tsv`. Смысл остальных полей и исходов не менялся; прогоны счётчика 2 `report` и `diff` не читают |
| счётчик 4 | Цена разреза или слияния без равенства по склейке — 3,5 вместо 2,5. При 2,5 разрез и слияние на трёх неверных токенах (5,0) выходили дешевле трёх пар 1:1 (6,0), и ряд неверных токенов Null сползал: токен получал вывод соседа и исход `botched` вместо `miss`. При 3,5 пара (7,0) строго дороже. Токены, которые сходятся склейкой (0,5), не затронуты. Пример: `chat.tatoeba/slip.warm/00fef6ae236e`. Числа `slip.*` до этой правки не сравнивать с числами после (замеры E2) |
| след и личные наборы, без смены определений исходов | След получает виды `kept` и `notJudged` (решение по оставленному слову и причина, почему слово не судили). Признаки `reason`, `margin` теперь есть и у оставленных слов; `margin` у переключения и правки прежний (счёт минус порог, ниже порога — `<3`), у оставленного слова — порог минус счёт. Счётчик 4, исходы и метрики не менялись: `cases.tsv`, `summary.json`, `counts.tsv`, `words.tsv` с выключенным следом и с включённым равны байт в байт (тест); меняются `slices.json` и `trace` в `events.jsonl`. След включён по умолчанию, поэтому у перепрогона старого набора в `slices.json` появляются срезы `reason` и `margin` (в том числе для `kept` и `notJudged`); остальные ключи и числа `slices.json` равны замеру до правки (тест `slicesOfAnOldSetDifferOnlyInTheReasonAndMargin`), счётчики и исходы те же. Личные наборы (`suite` `personal.`, `PEREKEY_EVAL_PRIVATE`): формат случая и исходы прежние; в `run.json` необязательное `personal`, файлы прогона личного набора несут хэши вместо слов. Прогоны до этой правки `report` и `diff` читают, как раньше |
| размеры `tiers.ci`, без смены определений | Урезаны размеры уровня `ci` у 16 наборов: `chat.tatoeba`, `lang.rus-se`, `lang.russian-se`, `mixed.uk-se`, `prose.*`, `tech.ruso` 20000 → 5000; `typos.none`, `typos.synth.*` 12000 → 4000; `doublecap`, `yo` 8000 → 3000; `hyphen` 6000 → 3000. Зачем: бюджет шага 300 с (РЕ9). С прежними размерами шаг на CI шёл 518 с даже при попадании в кэш базы (прогон 43090913702), с урезанными — 163 с при попадании и 238 с при промахе (прогоны 43085563904 и 43076870338): сэкономлено 355 с. Шум: планки `noWorse` сравнивают голову и базу на одних и тех же случаях, поэтому от размера не зависят; пороги мутантов замерены на урезанных размерах (раздел «Самопроверка и мутанты», запас вдвое). Формат, исходы, метрики и счётчик не менялись; `full` читает свои размеры |
| наборы классов, без смены определений | Манифест получает `reader: class` и объект `class`, `sampling: type`; единица без букв допустима (`numbers`). Поле `w` токена, метки `tags`, исходы, метрики и счётчик не менялись; `disputed` в наборах `class.*` и `protect.*` не считается и раньше (7.5). `build.json` получает блок `classes` только у наборов классов; `cases.tsv` и `summary.json` прежние |

| наборы правок слова, счётчик 4 | Новые значения без смены смысла: сценарии `fix`, `fix.merged`, `fix.spaced`, `keep` (манифест с `correction`), читатели `misspellings` и `typopairs`. Проверка случая 5.3 ужесточена: шаг `capsLock` делает буквы цели заглавными, и случай v1 с `capsLock: true` и строчной целью, который раньше проходил проверку, теперь её не проходит (в `eval/cases` таких нет). Проверка ослаблена в одном месте: токен с `err: hyphen` забирает из цели столько токенов, сколько нужно, чтобы буквы совпали (дефис, набранный пробелом, делит слово); остальные токены стоят один в один, с настоящими дефисами. Смысл полей случая, исходов и метрик не менялся; старые случаи проходят проверку, как раньше |
| наборы `learning.*`, без смены определений | Новая команда `learning` и свои метрики (раздел «Обучение»): они не входят в формат случая, исходы и счётчик. `EvalDesk.posted` и `Typist.events(of:)` — добавления; `events(for:)` и файлы прогона прежние (старые `cases.tsv`, `summary.json` и `result-*.json` совпадают байт в байт) |
| обучение, пересмотр E8 | `falseLearned` считает слова, выученные на очках случайных Backspace (раньше — выученные слова с `keep == 0` за весь прогон). `interventionsToSilence` — среднее по замолчавшим словам; рядом `wordsNeverSilent`. `learning vocabulary` читает `run.json` и отказывает на `testRevealed` и `personal`. `learning sweep` проверяет значения сетки до прогона. Исходы, счётчик и файлы `play` не менялись; меняются только отчёты `learning` |
| пакет случаев, без смены определений | Новая команда `cases pack` и каталог `eval/pack`. Формат случая, исходы, метрики, счётчик и файлы прогона не менялись: `cases build`, `play` и `report` работают, как раньше (тест `PackTests`, JSON `scripts/eval.sh` равны до и после) |
| настоящая программа (E9), без смены определений | Новые команды `perekey-e2e play`, `perekey-eval fidelity`, `perekey-eval cases fidelity`, файл `app.json` прогона и тип испытуемого `app` в `run.json`. Формат случая, исходы, метрики и счётчик не менялись: `Runner` получил `playApp`, играющий `play` как раньше (файлы `play` и JSON `scripts/eval.sh` равны до и после) |
