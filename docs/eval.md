# Стенд качества

Что меряет стенд, из чего он состоит и по каким правилам считает. Старый
замер классификатора (`perekey-eval run`, `scripts/eval.sh`) — в
`docs/classifier.md`; стенд его не трогает.

Стенд судит не одно слово, а набор. **Случай** — что делают пальцы человека и
какой текст он хотел. **Наборщик** превращает шаги случая в нажатия клавиш и
время. **Испытуемый** получает эти нажатия и отдаёт итоговый текст поля.
**Счётчик** сравнивает текст с задуманным и даёт каждому токену **исход**.

```
случай (.jsonl) ─► наборщик ─► события ─┬─► Null (без Perekey) ─┐
                                        └─► испытуемый ─────────┴─► счётчик ─► исходы ─► файлы прогона
```

Код: `Sources/PerekeyDesk` (стенд вокруг машины, без Foundation, как ядро) и
`Sources/PerekeyEvalKit` (случаи, наборщик, испытуемые, счёт, файлы).
`PerekeyCore`, `PerekeyInput` и `Perekey` о стенде не знают. Данные стенда —
в `eval/`, данные модели — в `data/`; сборщик модели `eval/` не читает
(тест `DataSeparationTests`).

## Случай

Файл `.jsonl`: одна строка — один случай, UTF-8, ключи отсортированы, без
пробелов. Чтение строгое: неизвестное поле, неизвестный шаг или другая
версия — ошибка. Строка, прочитанная и записанная снова, даёт те же байты.

| Поле | Обязательное | Смысл |
|---|---|---|
| `v` | да | Версия формата, `1` |
| `id` | да | `<набор>/<сценарий>/<12 hex>`: первые 12 hex FNV-1a 64 от полей `layouts`, `start`, `env`, `warmup`, `script`, `want`. Каждое поле — JSON с отсортированными ключами, между ними U+001F. Нет `env` — как `{}`, нет `warmup` — как `[]` |
| `suite`, `scenario` | да | Набор и сценарий |
| `split` | да | `dev` или `test`. Написанные руками случаи — `dev` |
| `epoch` | нет, 1 | Эпоха выборки |
| `layouts` | да | Снимки из `eval/layouts/` в системном порядке |
| `start` | да | Раскладка в начале, одна из `layouts` |
| `env` | нет | Среда, ниже |
| `warmup` | нет | Шаги до измеряемой части: их токены не считаются, порча видна как `spill` |
| `script` | да | Шаги измеряемой части |
| `want` | да | Текст, который человек хотел, целиком, вместе с `warmup` |
| `tokens` | да при `scoring: token` | Токен измеряемой части: `t` — текст; `lang` — язык или `-`; `err` — ошибка человека: `none`, `layout`, `typo`, `caps`, `doublecap`, `hyphen`, `yo`, `abbrev`; `accept` — другие верные формы; `tags`; `w` — вес, умолчание 1 |
| `scoring` | нет, `token` | `token` — исход по токенам; `case` — текст целиком и `checks` |
| `checks` | нет | `{"layout":"Russian"}` — раскладка в конце; `{"corrections":N}` — показано правок; `{"undone":N}` — отменено |
| `fold` | нет | `yo`: «ё» и «е» равны |
| `tags`, `meta` | нет | Классы случая; `meta` — любой JSON: `why` (что держит случай), `issue`, `status` у сбоев |

`env`: `app` (`com.apple.TextEdit`), `mode` (`auto`, `manualOnly`, `off`),
`settings` (пресет, `default`), `field` (`plain` или `blind`), `pace` (`calm`
или `burst`), `lag` (0), `prior` (счёт слов по языкам для `LanguagePrior`),
`exceptions`, `alwaysFix`, `secureInput` (false). В скобках — умолчание.

**Шаги.** Список закрыт.

| Шаг | Смысл |
|---|---|
| `{"type":"привет ","on":"Russian"}` | Нажать клавиши, которые печатают этот текст в раскладке `on`. Активная раскладка может быть другой: в этом ошибка. Символ, которого `on` не печатает без ⌥ и Caps Lock, — ошибка случая |
| `{"layout":"ABC"}` | Человек сам выбрал раскладку в системе |
| `{"hotkey":"switchLayout"}` | Сочетание действия из настроек случая: `switchLayout`, `convertLastWord`, `toggleAutoswitch`, `changeCase`, `undoLastCorrection`. Без привязки в пресете — ошибка случая |
| `{"key":"backspace","n":2,"mods":["option"]}` | Клавиша: `backspace`, `return`, `tab`, `escape`, `left`, `right`, `up`, `down`, `space`, `enter`; модификаторы `shift`, `option`, `command`, `control` |
| `{"click":"end"}` | Щелчок: `start`, `end`, число (каретка после стольких символов), `hint` (кнопка подсказки) |
| `{"focus":{"app":"…","secure":false,"known":true}}` | Смена фокуса; поле очищается, как новое |
| `{"mode":"manualOnly"}` | Режим программы |
| `{"capsLock":true}` | Caps Lock включён или выключен |
| `{"select":4}` | ⇧← столько раз |
| `{"secureInput":true}` | Secure Input |
| `{"wait":0.5}` | Пауза, секунды |
| `{"pace":"burst"}` | Сменить темп |
| `{"undo":"button"}` | «Отменить» в подсказке последней правки |

**Проверка** (`perekey-eval cases check`, и та же перед `play`):

1. Поля на месте, `v` равен 1, `id` равен хэшу. Неверный `id` команда
   печатает вместе с верным.
2. Каждый символ каждого `type` печатается в своей `on`. Раскладки, `start`,
   `on`, шаги `layout` — из `layouts`; пресет известен; у `hotkey` есть привязка.
3. **Текст цели** — что дали бы шаги, если бы каждый `type` печатался в своей
   `on`, с клавишами правки, щелчками и выделением. Его токены после
   `warmup` равны `tokens[].t`, где `err` — `none` или `layout`, и отличаются,
   где `err` другой.
4. Токенов измеряемой части `want` столько же, сколько `tokens`; токены
   `want` — это `warmup` и `tokens[].t` через пробел.
5. Строка канонична: ключи отсортированы, пробелов нет.

Случай с ошибкой не играется, команда выходит с кодом 2.

Написанные руками случаи: `eval/cases/flow.basics.jsonl` (поведение
программы вокруг слова, `scoring: case`) и `eval/cases/incidents.jsonl`
(реальные сбои; `meta.status`: `open` — ждёт починки, `fixed` — должен
проходить).

## Наборщик и стенд

**Наборщик** (`Typist`) — чистая функция случая: те же шаги, те же события.
Числа — в `Typist.Options`.

1. **Shift** нажимается как модификатор: Shift вниз, клавиша, Shift вверх.
   Заглавные подряд идут под одним удержанием. Одинокий Shift в пресете по
   умолчанию переключает раскладку, поэтому Shift вокруг клавиши обязателен.
   Тест: 1000 слов с заглавными не меняют раскладку.
2. **Темп.** `calm` — клавиша вниз через 0,05 с после прошлой клавиши
   вверх, вверх через 0,02 с, как `Desk.press`. `burst` — 0,03 и 0,01 с.
3. **Сочетание** берётся из настроек случая. Пауза 0,3 с после последней
   клавиши, модификаторы вниз, 0,08 с, вверх (`Desk.tap`): `ChordDetector`
   не считает сочетанием нажатие, начатое меньше чем через
   `minIdleAfterTyping` после набора. Двойное нажатие — два нажатия через
   0,1 с.
4. **Конец случая** — пауза 2 с: проходят сроки ограды, стенд догоняет.

Время считается в микросекундах, поэтому суммы шагов точны.

**Стенд** (`EvalDesk`) — система вокруг `InputMachine`, по образцу
`Desk` (`Tests/PerekeyCoreTests/Desk.swift`) и драйвера `perekey-bench`.

1. **Клавиша.** Сначала решение о событии, потом эффекты. `pass` и клавиша
   вниз не от Perekey печатается в поле в раскладке программы; `hold`
   ждёт `releaseHeld`; `drop` — ничего. Клавиши с ⌘ и ⌃ не печатают.
   `flagsChanged` не придерживается, что бы ни ответила машина (`Desk.tap`).
   Caps Lock — состояние стенда: пока он включён, к клавишам добавляется
   его флаг; эффект `capsLockOff` его выключает.
2. **Поле** с кареткой и выделением слева от неё (`TextField`): печать
   заменяет выделение, Backspace, ⌥⌫ (слово), ←, →, ↑ (в начало), ↓ (в
   конец), Return (`\n`), Tab (`\t`), щелчок.
3. **Эффекты** — как `InputEngine.execute`. Пара `selectLayout` и
   следующий за ним `retype` и `convertSelection` ждут главного потока,
   пока стенд догонит. `retype` без `selectLayout` (правка в своей
   раскладке) исполняется сразу. Проверка каретки берётся в момент эффекта
   `retype`, как `InputEngine.beginCheck`: в поле `plain` перенабор слова
   (`deleteCount` > 0) с текстом слева от каретки, который не кончается на
   `expected`, отменяется. Поле `blind` (нет AX: Electron, терминал) не
   сверяет. `releaseHeld` возвращает придержанное как `replayed` через
   0,0005 с; `scheduleDeadline` запоминает срок; остальное идёт в журнал.
   «Отменить» шлёт `undoLastCorrection` с `seq` последней правки; правок
   не было — шаг пропускается.
4. **Перенабор** — как `InputEngine.postIfPending`. Машина ждёт другой
   `seq` (ограда уже снята) — перенабор не печатается, машина получает
   `inputLost`. Проверка каретки не прошла — `retypeCancelled`. Иначе
   удалить, вставить, `retypePosted`, синтетические клавиши.
   **Догнать** (`settle`), как `Desk.settle`: по очереди ответить на чтение
   выделения (выделенный текст или пустой); выбрать раскладку, напечатать
   её перенабор, затем `layoutChanged`.
5. **Отставание.** Стенд догоняет, когда наборщик прислал ещё `env.lag`
   нажатий после появления работы, или когда между событиями прошло не
   меньше 0,05 с модельного времени — что раньше. `lag` 0 — сразу после
   события. В темпе `calm` промежуток между клавишами 0,05 с, поэтому стенд
   догоняет перед каждой клавишей, как `Desk.press`.
6. **Сроки.** Перед событием со временем не меньше срока стенд шлёт
   `.deadline`. Пауза сначала догоняет, потом двигает время и шлёт
   созревшие сроки: последняя правка случая не теряется до срока ограды.
7. **Старт.** `InputMachine(settings:layouts:currentLayout:classifier:)`,
   `focusChanged(env.app)`, `appModeChanged(env.mode)`, при `env.prior` —
   `languageContextChanged`, при `env.secureInput` — `secureInputChanged`.
   В режиме `off` программа убирает сочетания (`InputController`), и стенд
   шлёт `settingsChanged` без них.

**Пресеты настроек** (`EvalSettings`):

| Пресет | Что включено |
|---|---|
| `default` | как в выпуске: автопереключение, опечатки, двойные заглавные, перенабор фразы. Тест сверяет его с `Settings()` поле за полем |
| `all` | всё из `TextCorrections`: плюс Caps Lock, аббревиатуры, «ё», дефис |
| `layout-only` | только автопереключение |
| `off` | ничего само; ручные сочетания работают |

`env.exceptions` и `env.alwaysFix` дописываются в пресет.

**Испытуемые.**

- `machine` — `InputMachine` в `EvalDesk` с моделью прогона. Модель и
  классификатор создаются один раз на набор языков. `--options <json>` —
  поля `Classifier.Options` поверх умолчаний; таблица имён — в
  `ClassifierOptions`, тест падает, если в `Options` появится поле, которого
  в ней нет. Пороги `TypoCorrector` снаружи не задать: `WordJudge` создаёт
  корректор с умолчаниями.
- `null` — поле без переключателя: клавиши в активной раскладке, выбор
  раскладки человеком, клавиши правки, щелчки, своё сочетание
  `switchLayout` (человек без Perekey переключает системным). На другие
  сочетания не отвечает. Null — постоянная база исходов, поэтому его
  сочетание подчиняется тем же правилам, что у машины: в режиме `off` его
  нет (программа убирает сочетания), под Secure Input тоже; Caps Lock и
  клавиши рвут сочетание в том же порядке, что `InputMachine`.
- `oracle` — возвращает `want`. Для проверки случаев и счётчика.

**След.** Что машина знает о своих действиях: переключение, правка (вид,
причина, счёт, «внутри слова»), отмена, отменённый перенабор. Запись
привязана к событию наборщика, которое попросило перенабор. Счётчик по следу
исходов не меняет: след даёт только метки и признаки.

## Исходы

**Токен** — наибольший отрезок без пробельных символов. Пробелы и переводы
строки в конце текста не считаются.

**Выравнивание** (`Aligner`). Правка может слить или разрезать токены
(«во первых» → «во-первых»). Равные списки токенов идут токен к токену.
Иначе — самое дешёвое выравнивание:

| Операция | Цена |
|---|---|
| 1:1, равны | 0 |
| 1:1, не равны | 1 + расстояние Левенштейна / длину большего |
| 2:1 или 1:2, склейка двух без пробела или через дефис равна одному | 0,5 |
| 2:1 или 1:2 иначе | 2,5 |
| токен пропал или лишний | 2 |

При равной цене: 1:1, слияние, разрез, пропажа, лишний. Правило склейки
только сопоставляет токены. Группа токенов `want` (один токен или два при
слиянии) верна, если текст вывода, сопоставленный ей, равен тексту группы
по свёрткам или входит в `accept` первого токена группы. «во первых» при
`want` «во-первых» неверно, «по новому» при «по-новому» — тоже, у Null и у
испытуемого одинаково. Слияние без `accept` всегда неверно (определение 7.2). Пропавший токен неверен. Лишний токен вывода
делает неверной группу слева от себя целиком, оба токена слияния (первый
токен, если слева ничего нет). Вывод Null выравнивается с тем же `want`
тем же правилом.

**Исход токена** измеряемой части:

| У Null | У испытуемого | Исход |
|---|---|---|
| верно | верно | `ok` |
| верно | неверно | `harm` — вред |
| неверно | верно | `fixed` — починено |
| неверно | неверно, вывод тот же | `miss` — пропуск |
| неверно | неверно, вывод другой | `botched` — порча |

Токен `warmup`, вышедший неверно, — `spill`. Определение не знает, как
устроен испытуемый: счёт получает только случай и два текста.

Метки к `harm` и `botched`: `form` — `layout`, если вывод равен клавишам
токена в другой раскладке случая, иначе `edit`; `cascade` — испытуемый сам
сменил раскладку перед токеном (после последнего выбора человека), а сам
токен не трогал (по следу).

**Случай.** `exact` — все токены верны, `warmup` тоже; для `scoring: case` —
текст (без пробелов в конце, со свёртками) равен `want`.

**Проверки случая** (`checks`: раскладка в конце, показано и отменено
правок) читают то, что испытуемый сообщает о себе, а счёт — только текст
(правило 2.7). Поэтому их считает не счётчик, а `Runner.failedChecks` над
`RunResult`: это метка случая. На `exact`, исходы и код возврата она не влияет:
`failedChecks` — только метка, гейт по ним — дело E6. В
файлах прогона — столбец `checks` и счётчик `checksFailed`. `lag` в сценариях `slip.*` и `stuck` — сколько токенов от первого
токена с `err: layout` до первого верного; верного нет — длина измеряемой
части. **Событие вреда** — подряд идущие токены `harm` одного случая.

**Признаки токена** для срезов: `lang`, `len` (`1-2`, `3`, `4`, `5-7`,
`8+` букв), `pos` (`first`, `mid`, `last`), `ctx` (`cold`, `agree`,
`against`, `mixed` по трём предыдущим словам), `cap` (`lower`, `Title`,
`UPPER`, `inner`, `mixed`), `punct` (`none`, `lead`, `trail`, `both`,
`inside`), `digits`, `err`, `end` (`space`, `punct`, `return`, `tab`,
`none`), `tags`; из следа — `reason`, `margin` (запас до порога: `<3`,
`3-10`, `10+` бит), `early`, `kind`.

## Метрики

Счёт — по токенам измеряемой части; «слова» — токены хотя бы с одной
буквой. На 1000 слов, ‰:

| Метрика | Формула |
|---|---|
| В — вред | `harm` / слова; рядом события вреда / слова |
| П — пропуск раскладки | `miss` с `err: layout` / токены с `err: layout` |
| Пч — порча | `botched` / токены с `err` не `none` |
| О — остаток | неверные у испытуемого / слова |
| О₀ — без Perekey | неверные у Null / слова |
| Чисто | доля случаев `exact` |

Интервалы, профили, срезы и сравнение двух прогонов — следующие лейны.

## Команды

```
perekey-eval cases check <файлы .jsonl>
perekey-eval cases list  <файлы .jsonl> [--suite X] [--scenario Y] [--split dev|test] [--reveal-test]
perekey-eval cases build [--suites <каталог>] [--cache <каталог>] [--tier ci|full] [--out <каталог>]
                    [--only <набор,...>] [--epoch <n>]
perekey-eval play   --cases <файлы или каталог> --model <каталог> --out <каталог прогона>
                    [--system machine|null|oracle] [--options <json>] [--settings <пресет>]
                    [--only <набор,...>] [--split dev|test|all] [--reveal-test]
perekey-eval case   --cases <файлы> --id <id> --model <каталог> [--system …] [--reveal-test]
perekey-eval selfcheck --cases <файлы или каталог> --model <каталог>
                    [--suites <каталог> --cache <каталог> --tier ci|full]
```

Все берут `--layouts <каталог>` (умолчание `eval/layouts`). `play` играет
каждый случай на испытуемом и на Null. `case` печатает один случай по
событиям: что вернула машина, текст поля, раскладку; слова части `test` —
только с `--reveal-test`. Коды выхода: 0 — успех; 1 — самопроверка не
прошла; 2 — ошибка входа.

**Часть `test`** (правило 2.8). Без `--reveal-test` ни файлы прогона, ни
сообщения команд не содержат слов случаев части `test`: на их месте
`(test)`. `play --reveal-test` пишет слова и ставит в `run.json`
`testRevealed: true`. `cases check` описывает ошибки случая `test` без его
слов.

`selfcheck` проверяет инварианты: Null не вредит и не чинит; Oracle точен
(по тексту: раскладки и счёта правок у него нет); машина с пресетом `off`
печатает то же, что Null, на случаях без сочетаний и «Отменить»; два прогона
машины дают те же байты `cases.tsv` и `summary.json`; каждый случай
проходит проверку. С `--suites` самопроверка собирает каждый набор дважды и сравнивает
SHA-256 файла и отчёт сборки; без `--suites` этот пункт пропускается.

Пример: `perekey-eval selfcheck --cases eval/cases --model .build/model`.

## Корпусные наборы

Набор — случаи одного происхождения. Манифест `eval/suites/<набор>.suite.json`
говорит, откуда текст, на каких раскладках его печатает человек и сколько
токенов брать. Манифест читают строго: неизвестное поле, сценарий или
значение — ошибка; имя файла равно полю `suite`.

| Поле | Смысл |
|---|---|
| `suite`, `version` (1), `about`, `license` | Имя, версия манифеста, описание, лицензия источника |
| `reader`, `source` | `tatoeba` или `stackexchange`; файлы кэша данных через запятую (`tatoeba/rus_sentences.tsv.bz2,tatoeba/eng_sentences.tsv.bz2`) |
| `sampling` | `token` — текст как написан. `type` (список слов) строят наборы классов; этот сборщик на нём отвечает ошибкой |
| `layoutSets` | Пары раскладок: одна латинская (`ABC`), одна кириллическая. Предложение попадает в пару по хэшу ссылки |
| `scenarios` | Из `clean.cold`, `clean.warm`, `slip.cold`, `slip.warm`, `stuck`, `clean.toggle` |
| `epoch`, `seed` | Номер выборки и зерно. Порядок единиц задаёт `seed + epoch` |
| `tiers` | `{"ci":N,"full":M}` — сколько токенов измеряемой части брать на каждый сценарий |
| `split` | `{"dev":20,"by":"unit"}` — доля части `dev` в процентах |
| `filter` | `minTokens`, `maxTokens`, `requireScripts` (`cyrillic`, `latin`) |
| `normalize` | `keyboard` (умолчание): « » “ ” „ → `"`, ‘ ’ ʼ → `'`, — – → `-`, … → `...`, неразрывный пробел → пробел. Раскладки печатают только эти знаки без ⌥; без свёртки большая часть русских предложений с тире непечатна. `none` — как написано |
| `transform` | `lowercase`, `stripPunctuation` (без знаков, кроме `'` и `-` внутри слова): строка чата |
| `settings`, `end`, `fold`, `tags` | Пресет настроек случая (`default`); конец случая `space` (умолчание), `return`, `none`; свёртки; метки случая |

**Читатели.** Tatoeba: `id`, язык, текст через табуляцию из `.bz2`; ссылка
`tatoeba:<язык>#<id>`. Stack Exchange: `Posts.xml` из `.7z`, читает системный
`tar`; ссылка `post:<Id>#<n>`, `n` — номер предложения в посте. Оба читают
потоком по строкам: дамп в гигабайт целиком в память не попадает. Пост:
`<pre>…</pre>` вырезается целиком; `<code>…</code>` в строке остаётся, его
токены получают метку `code`; блочные теги (`p`, `br`, `li`, `blockquote`,
`h1`–`h6`…) делят абзацы, остальные теги исчезают без пробела; сущности
раскрываются. Единица — предложение. Предложение кончается на `.`, `!`, `?`
(и закрывающих знаках после них), за которыми идут пробел и заглавная буква
или цифра. Одна буква перед точкой («т. д.», «А. С.») — сокращение, не конец.

**Токены.** Токен режется на отрезки одного письма; знаки и цифры идут с
отрезком перед ними, знаки перед первой буквой — с первым отрезком.
«USB-порт» — `USB-` и `порт`, метка токена `mixed-token`. Язык токена — по
первой букве: кириллица — язык кириллической раскладки пары (`ru`, `uk`,
`be`, `kk`), латиница — `en`, нет букв — `-`. Токен без букв целится в
раскладку токена перед ним, первые такие токены — в раскладку первого токена
с буквами. Предложение с буквой другого письма или с символом, который
раскладка пары печатает только с ⌥ или Caps Lock, в набор не попадает.

**Сценарии.** Пальцы целятся в раскладки `X₀`, `X₁`… по токенам.

| Сценарий | Старт | Выбор раскладки в шагах | `warmup` |
|---|---|---|---|
| `clean.cold` | `X₀` | `layout` перед каждой сменой цели | нет |
| `clean.warm` | раскладка `warmup` | то же, включая первый шаг | предложение другого письма, набранное верно |
| `slip.cold` | вторая раскладка пары | `layout` на сменах цели, кроме первого шага | нет |
| `slip.warm` | раскладка `warmup` | как у `slip.cold` | то же, что у `clean.warm` |
| `stuck` | `X₀` | нет | нет |
| `clean.toggle` | `X₀` | `hotkey switchLayout` на сменах цели | нет |

`stuck` и `clean.toggle` строятся только для предложения с обоими письмами.
У одноязычного они равны `clean.cold`; такие случаи сборщик не строит и
считает под причиной `singleScript`. `warmup` — короткое (3–8 токенов)
предложение из того же источника в одном письме, противоположном письму
первого токена; его выбирает хэш ссылки из первых 2000 по порядку выборки.
`want` — `warmup`, пробел и токены. `err` ставит прогон Null: `layout` у
токенов, которые Null напечатал неверно, иначе `none`. Если в `clean.*` Null
ошибся, случай не строится (причина `nullWrongInClean`): ошибка набора там —
признак бага сборщика, а не человека.

**Выборка.** Первый проход читает весь источник и для каждой единицы считает
ранг: первое число `SplitMix64` с зерном `FNV-1a 64 (ссылка) ⊕ (seed +
epoch) · 0x9E3779B97F4A7C15`. Он хранит первые по рангу `4 · tier` единиц на
файл источника и ничего не разбирает. Файлы источника берутся по очереди:
русские и английские предложения Tatoeba весят поровну, пока файл не
кончится. Второй проход разбирает единицы по порядку, пропускает дубли
текста и строит сценарии, пока в каждом сценарии не наберётся токенов по
уровню. Разобранные единицы — случайная выборка источника, поэтому доли
причин отброса в `build.json` описывают источник. Новая эпоха берёт другой
порядок; единицы соседних эпох могут совпасть.

**Части.** `dev`, если `FNV-1a 64 (набор + U+001F + ссылка) mod 100 <
split.dev`. Все сценарии предложения лежат в одной части.

**Команда `cases build`** пишет `<out>/<набор>.jsonl` (умолчание
`.build/quality/cases/<уровень>/`) и `build.json`. В `build.json` по набору:
единицы источника, отобранные, разобранные, причины отброса, случаи, токены
и ошибки раскладки по сценариям, размер пула `warmup`, нехватка токенов
(`shortfall`) и SHA-256 файла. Слов в `build.json` и на экране нет. Тот же
вызов даёт те же байты.

| Причина (`drops`) | Что значит |
|---|---|
| `tooShort`, `tooLong` | Токенов меньше `minTokens` или больше `maxTokens` |
| `noLetters`, `otherScript` | Нет букв; буква письма, для которого нет раскладки |
| `missingScript` | Нет буквы письма из `requireScripts` |
| `unprintable` | Символ, который раскладка пары печатает только с ⌥ или Caps Lock, или не печатает |
| `duplicate` | Тот же текст уже взят |
| `singleScript`, `noWarmup`, `nullWrongInClean` | Причины по сценарию, см. выше |

## Файлы прогона

`<каталог прогона>/`:

| Файл | Что внутри |
|---|---|
| `run.json` | Версии формата и счётчика, коммит, SHA-256 моделей, испытуемый, `--settings`, `--options`, файлы случаев с SHA-256, часть, `--only`, `testRevealed` |
| `cases.tsv` | Строка на случай: `id`, слова, токены `warmup`, буква исхода на каждый токен (сначала `warmup`): `o` ok, `F` fixed, `H` harm, `M` miss, `B` botched, `S` spill; `-` у `scoring: case`; `exact` (1 или 0); `lag` (`-`, если не считается); `checks` (`ok`, `failed`, `-` без проверок) |
| `events.jsonl` | Строка на токен с исходом не `ok`: `id`, номер, `want`, `null`, `out`, исход, метки, признаки, след. Для `scoring: case` с другим текстом — строка `fail`; для случая с невыполненными `checks` — строка с ними (`fail` или `checks`). Слова части `test` — `(test)` без `--reveal-test` |
| `summary.json` | Счётчики и метрики по набору и сценарию, итог, сбои по статусам |

`cases.tsv` и `summary.json` зависят только от случаев, модели и кода.

## Чего стенд не моделирует

- **Проверка каретки строже настоящей.** Стенд сравнивает текст поля
  точно. Настоящий `CaretCheck` видит то, что даёт AX: автоскобки и
  предиктивный ввод программы, ответ «не знаю» и таймаут AX, после которых
  перенабор идёт без сверки.
- **Перенабор через AX** (`Retype.viaAccessibility`) и его отказ: стенд
  всегда печатает перенабор клавишами.
- **`ReplayGate`**: в стенде повторы всегда возвращаются и сразу, порядка
  ожидания повторов в `PerekeyInput` и их потери нет.
- **Кнопка «Отменить» без `HintLifetime`**: подсказка в стенде живёт, пока
  её правка последняя; срок показа (3 с, следующее слово) не учитывается.
  `HintLifetime` лежит в слое программы, а `PerekeyDesk` зависит только от
  ядра.
- **Сроки по модельному времени**: стенд догоняет по правилу отставания,
  срок ограды наступает по часам наборщика, а не по настоящим таймерам;
  настоящей задержки AX и программы нет.
- Автодополнение и автозамену программ.
- Подсказку и её вопросы («Только здесь / Везде / Нет»).
- Обучение на отменах между случаями: машина шлёт `undoSettled`, а список
  исключений пополняет программа. Каждый случай начинается с пресета.
- Пороги `TypoCorrector` из командной строки.
- Причину решения для оставленных слов: след берётся только из
  `Effect.corrected`, отмен и отменённых перенаборов.

Это закрывает испытуемый App — настоящая программа.
